## 目标

根据用户输入的中国城市，取得该城市的直接下级行政单位，逐行政单位检索政府或教育行政部门公开的非高校学校名录，提取学校名称、学校类型、办学性质和地址，经公共地址组件规范化与地图兜底后，生成行政单位级工作簿和城市汇总工作簿。

政府或教育行政部门发布的名录是学校范围、学校类型、办学性质和原始地址的事实来源。地图不参与学校名录补充，只用于处理已经从政府名录提取出的学校地址或学校名称。

## 输入

接受一个中国城市名称，例如：

- 广州市
- 广州

输入只处理地级单位或直辖市，不要求用户同时提供省级名称。城市标准化成功后，后续流程统一使用公共城市组件返回的 `city_context`。

如果用户没有提供城市，先询问城市名称。运行前还需要确认使用的 Python 环境；已经确认过的环境无需重复询问。

## 输出目录与文件

全部文件写入：

`<项目根目录>/output/<标准城市名>/<YYYY-MM-DD>/Basic_Education/`

每个直接下级行政单位使用一个同名子目录，例如：

`E:\DSH\output\广州市\2026-08-28\Basic_Education\越秀区\`

行政单位目录保存：

- 下载的政府原始文件。
- `government_source.json`。
- `extraction_plan.json`。
- 可选的 `<原文件名>.vision.json`。
- `address_records.json`。
- `processed_address_records.json`。
- `基础教育学校信息_<行政单位>.xlsx`。

城市最终工作簿为：

`基础教育学校查询_<标准城市名>_<YYYY-MM-DD>.xlsx`

城市工作簿包含一个“学校信息”总表，以及每个行政单位各一张分表。

## 表字段

工作簿按以下顺序输出：

| 字段 | 内容 |
| --- | --- |
| 序号 | 每张工作表按最终输出顺序重新编号。 |
| 行政单位 | 城市直接下级行政单位名称。 |
| 学校名称 | 政府来源中的学校名称；明确拆出校区时为学校名称加校区名称。 |
| 学校类型 | 规范化后的一个或多个学校类型。 |
| 办学性质 | 公办、民办或政府来源中的其他原文。 |
| 地址 | 政府资料规范地址或高德地图唯一兜底地址。 |
| 地址获取方式 | 官网提取或地图信息 |
| 地图匹配状态 | 地图与来源地址的匹配状态 |
| 发布日期 | 政府来源发布日期；来源没有日期时为提取当天日期。 |
| 信息来源 | 实际包含学校名录的政府页面、文件名和可定位的原始行号。 |

## 第一步：标准化城市并取得行政单位

运行：

```text
python -m query_city_core.city --city <用户城市>
```

公共城市组件返回：

- `input_city`：去除首尾空白后的用户输入。
- `city_name`：标准城市名。
- `province_name`：非直辖市的上级省级单位；直辖市为空值。
- `subdivisions`：高德返回并整理后的直接下级行政单位。

例如，输入“广州”后得到标准城市名“广州市”，并取得越秀区、海珠区、荔湾区等直接下级行政单位。

后续文件必须原样传递完整 `city_context`。每个行政单位对象也必须原样取自 `city_context.subdivisions`，不得自行增删、合并、改名或继续拆分到街道、乡镇。

## 第二步：按行政单位分配任务

主 Agent 为每个 `subdivisions[].name` 创建同名目录，并按行政单位划分互不重叠的检索任务。

子 Agent 负责一个行政单位中的：

- 政府来源检索与质量判断。
- 原始文件下载。
- `government_source.json`。
- 提取计划复核。
- 学校记录提取和公共地址处理命令。

主 Agent 负责城市标准化、任务分配、行政单位结果验收和城市总表生成。子 Agent 不写城市总表，也不继续向下委派。

## 第三步：检索政府学校名录

每个行政单位分别检索幼儿园、小学、初中和高中。检索顺序为：

1. 当前行政单位的教育行政部门。
2. 当前行政单位的政府门户。
3. 上级教育行政部门。
4. 政府数据开放平台。

只采用政府或教育行政部门发布，且正文、附件或分页实际包含学校名录的来源。通知页面只有在正文或附件真正列出学校时才采用。

政府来源同时列出一贯制学校、完全中学、特殊教育、中等职业教育、职业高级中学、技工院校、专门学校或其他非高校类型时一并纳入，不因为不属于四类必查学校而删除。

时间范围按以下顺序扩大：

1. 先检索当年。
2. 再检索去年。
3. 仍无合格来源或存在覆盖缺口时，才扩大到前年。

候选来源按官方性、时效性和信息量选择，不因文件格式不同改变优先级。地图、百科、媒体、自媒体、择校网站和第三方学校数据库不得作为学校名录来源。

## 第四步：保存来源

入选后立即把原始 HTML、Excel、Word、PDF 或图片保存到当前行政单位目录。

分页 HTML 保存全部名录页；附件保留原文件名和格式。

`government_source.json` 由 Agent 写入，脚本只校验和读取。主要字段为：

| 字段 | 责任 |
| --- | --- |
| `stage` | 固定为 `basic_education_government_source`。 |
| `city_context` | 主 Agent 传入，子 Agent 原样写入。 |
| `administrative_unit` | 原样取自 `city_context.subdivisions`。 |
| `processing_status` | Agent 根据检索结果判断。 |
| `school_type_coverage` | Agent 分别判断各类学校的覆盖状态。 |
| `items` | Agent 确认采用并已经保存到本地的政府来源。 |

四类必查学校与整体状态的关系为：

| `processing_status` | `items` | 四类必查学校状态 |
| --- | --- | --- |
| `completed` | 非空 | 全部为 `covered`。 |
| `partial` | 非空 | 至少一类不是 `covered`。 |
| `no_official_source` | 空 | 全部为 `no_official_source`。 |
| `source_unusable` | 空 | 至少一类为 `source_unusable`，其余只能为 `source_unusable` 或 `no_official_source`。 |

每个来源记录保存标题、发布部门、发布日期、落地页、实际名录链接、覆盖类型、是否包含地址和本地文件名。文件格式由读取脚本根据本地文件后缀识别，Agent 不重复填写。

**例子：** 越秀区教育局发布一份同时包含幼儿园和小学的 Excel，但没有找到初中和高中名录。Agent 把 Excel 保存到越秀区目录，`processing_status` 写为 `partial`，幼儿园和小学写 `covered`，初中和高中写 `no_official_source`，并在 `items` 中记录该 Excel 的政府页面和本地文件名。

## 第五步：检查来源并生成提取计划

脚本先校验城市上下文、行政单位、状态组合和来源字段，再根据文件后缀选择读取器：

| 文件 | 处理方式 |
| --- | --- |
| `.html`、`.htm` | 读取 HTML 表格，并分析重复页面结构。 |
| `.doc`、`.docx` | 使用 LibreOffice 临时转换为 HTML，再按 HTML 读取。 |
| `.xls`、`.xlsx` | 读取全部工作表。 |
| `.pdf` | 读取逐页文字层并检测表格。 |
| `.jpg`、`.jpeg`、`.png`、`.webp` | 标记为需要视觉处理。 |
| `.vision.json` | 按页读取 Agent 生成的二维行列结果。 |

脚本检查工作表、页码、表格、表头和重复 HTML 块，尝试识别：

- 学校名称列。
- 地址列。
- 学校类型列。
- 办学性质列。
- 数据开始行。
- 固定值和向下填充列。
- 根据非零招生人数推断学段的列；该判断不用于过滤学校记录。
- 应排除的说明、合计或空行。

脚本只提出候选规则，不自行批准。

## 第六步：Agent 复核提取计划

Agent 检查计划中的文件、页码、工作表、表格位置、学校列、地址列、学校类型、办学性质、固定值、向下填充列和排除行。

正确规则设为 `approved = true`，对应来源设为 `review_status = ready`。Agent 不手工抄写最终学校记录，避免绕过统一的学校类型规范、来源定位和去重逻辑。

扫描 PDF 缺少可用文字层或图片来源被标记为 `needs_vision` 时：

- 有视觉能力：按页面生成 `<原文件名>.vision.json`，把文件加入来源的 `derived_files`，重新运行 `inspect`。
- 没有视觉能力：只在文件确实为 `needs_vision` 时，将来源设为 `review_status = skipped`、`skip_reason = no_vision_capability`。

视觉结果中的 `rows` 必须保留原始行列，不补写图片中不存在的学校、地址或类型。

## 第七步：提取学校记录

脚本只执行 `review_status = ready` 来源中 `approved = true` 的规则。支持的规则包括二维表格、Excel 工作表、PDF 表格、视觉表格、重复 HTML 结构和文本正则结构。

如果来源尚未复核、没有批准规则、规则找不到目标表格或一条学校都没有提取到，脚本记录错误。只有输出 `stage = address_records` 且 `metrics.error_count = 0` 才能进入公共地址处理。

每条地址输入记录包含：

```json
{
  "place_name": "示例小学",
  "original_address": "越秀区示例路1号",
  "source_nature": "government_information",
  "source_reference": "政府名录链接 | 本地文件 | 原始位置",
  "attributes": {
    "administrative_unit": "越秀区",
    "school_type": "小学",
    "school_nature": "公办",
    "publication_date": "2026-08-01"
  }
}
```

来源没有地址时，`original_address` 保持为空字符串，不推断或编造。`source_reference` 优先使用实际名录链接，并附带本地文件和表格、工作表、页码或行号定位。

## 第八步：规范学校字段和拆分明确校区

脚本在生成地址记录时执行确定性规范：

- 移除中文学校名称中因换行或提取产生的内部空白，保留拉丁文字中的正常空格。
- 将“完中”规范为“完全中学”。
- 将“职业高中”规范为“职业高级中学”。
- 将“中职”或“中等专业”规范为“中等职业学校”。
- 将“技师学院”或“技工学校”规范为“技工院校”。
- 将“培智”规范为“特殊教育学校”。
- 明确包含“公办”或“民办”的办学性质分别规范为“公办”或“民办”，其余保留政府原文。
- 来源发布日期为空时，当前代码使用提取当天日期。

同一地址字段明确包含多个校区时，脚本可以拆成多条记录，包括：

- `东校区：地址；西校区：地址`。
- `（东校区）地址；（西校区）地址`。
- `地址（东校区）/地址（西校区）`。

拆分后地点名称使用“学校名称 + 校区名称”。只有标签明确且每个标签都能取得地址时才拆分；无法稳定拆分时保留原学校名称和完整原始地址。

**例子：** “示例中学，东校区：越秀区甲路1号；校本部：越秀区乙路2号”生成“示例中学东校区”和“示例中学校本部”两条地址记录。若文本只有“越秀区甲路1号、越秀区乙路2号”而没有校区标签，则不猜测两个地址分别属于哪个校区。

## 第九步：处理地址

公共地址层逐条处理输入记录，并原样传递 `city_context`、`source_reference` 和 `attributes`。

基础教育记录的 `source_nature` 固定为 `government_information`，因此地址路由为：

| 政府来源地址 | 地图处理 | 最终地址 |
| --- | --- | --- |
| 包含道路、门牌等实际地址 | 不调用地图 | 使用规范化后的政府资料地址。 |
| 只有学校名称、行政区或空地址 | POI 查询 | 仅名称、城市、行政单位和类型均匹配，且只剩一个不同地址时采用地图地址。 |
| 跨城市冲突或没有合格候选 | 不采用候选 | `final_address` 保持为空。 |

POI 查询中的多个候选只在当前一次查询范围内按规范地图地址去重。存在多个不同地址时标记为 `ambiguous`，不生成最终地址。

公共地址层不比较不同输入记录，不合并同址学校或校区，也不删除最终地址为空的记录。每条输入对应一条输出，并增加 `normalized_address`、`map_address`、`map_match_status`、`final_address`、`final_address_source` 和原因字段。

**例子：** 政府名录给出“示例小学，越秀区甲路1号”，公共层补齐标准城市前缀后直接采用政府地址，不请求地图。政府名录只给出“示例小学”且地址为空时，公共层在广州市越秀区内进行 POI 查询；只有一个名称和类型均符合的地址时才采用。

## 第十步：去重、排序和工作簿生成

学校记录从政府来源进入最终工作簿时依次经过：

```text
政府原始文件
→ 已批准提取规则生成的学校记录
→ 提取后的同名同原始地址去重
→ 公共地址逐条规范化和地图处理
→ 最终输出同址学校身份去重
→ 过滤空地址、排序并写入 Excel
```

各阶段使用不同的键，不能把后一阶段的结果理解为前一阶段已经完成的去重。

### 1. 来源与提取规则

Agent 只把确认采用且已经保存到本地的政府名录写入 `government_source.json.items`。脚本随后只执行 Agent 批准的规则。同一个政府文件中的不同工作表、表格或页面可以分别形成规则；不同来源也可能重复列出同一学校。

这一阶段不按学校身份合并记录。

### 2. 提取后的精确去重

全部批准规则执行完成后，`normalize_school_records.py` 使用以下精确键去重：

`(place_name, original_address)`

规则为：

- 学校名称和原始地址都完全相同，只保留发布日期最新的记录；发布日期相同则保留第一次出现的记录。
- 被合并记录的学校类型全部追加到保留记录，按首次出现顺序去除重复类型。
- 学校名称相同但地址文字存在城市前缀、空白、标点或门牌差异时继续保留。
- 地址相同但学校名称不同，继续保留。
- 最新记录作为基础记录，因此办学性质和信息来源也来自最新记录；这一层不额外合并办学性质和来源。

### 3. 公共地址处理

公共层不进行跨记录去重。上一步保留两条时，即使规范化后得到相同的 `final_address`，仍会输出两条 `processed_address_records.items`。

地图内部的候选去重只服务于一条记录的一次 POI 查询，不会合并两个学校输入。

**例子：** “越秀区甲路1号”和“广州市越秀区甲路1号”分别进入公共层，规范化后都可能得到“广州市越秀区甲路1号”，但公共层仍保留两条结果。

### 4. 最终输出同址学校身份去重

`build_excel.py` 先删除 `final_address` 为空的记录，再为每条记录计算学校身份。

学校身份规范过程为：

1. 删除学校名称中的空白、括号、方括号、中点和项目符号。
2. 删除开头的标准城市名。
3. 删除随后开头的行政单位名。
4. 删除学校名称末尾的“小学、初中、高中”学段表达。
5. 对符合规则的“校本部、本部、某校区、某园区”后缀取基础学校名称。

最终去重键为：

`(administrative_unit, final_address, normalized_school_identity)`

同键记录处理规则为：

- 合并学校类型。
- 办学性质优先保留首次记录的非空值；首次为空时使用后续非空值。
- 发布日期较新的记录替换为基础展示记录，因此学校名称和信息来源也随较新记录更新。
- 合并后的学校类型和办学性质继续写回所保留记录。

**例子：** “广州市示例中学（初中部）”和“示例中学”在同一行政单位拥有相同最终地址，规范学校身份都为“示例中学”，因此合并为一条，并合并两条学校类型。若第二条发布日期更新，则最终展示第二条名称和来源。

这一层也有明确边界：不同学校主体即使同址也不会合并；不同最终地址不会合并；相同学校的不同校区如果规范身份和最终地址都相同，当前代码会合并。

### 5. 排序与城市汇总

每个行政单位内按学校类型稳定排序，主要顺序为：

1. 幼儿园。
2. 小学。
3. 九年一贯制学校。
4. 初中。
5. 完全中学。
6. 高中。
7. 十二年一贯制学校及其他一贯制学校。
8. 特殊教育学校。
9. 中等职业学校、职业高级中学、技工院校、专门学校。
10. 其他官方类型。

同一优先级保留输入顺序。每张工作表重新生成连续序号。

城市“学校信息”总表按行政单位目录收集顺序拼接已经处理好的分表记录，不再执行跨行政单位去重。每条记录的 `attributes.administrative_unit` 必须与所在目录名称一致，否则停止生成。

## 过程记录

每个行政单位保留：

- 政府来源检索结论和四类学校覆盖状态。
- 原始政府页面或附件。
- 文件检查结果和 Agent 批准的提取规则。
- 可选的视觉行列结果。
- 提取数量、缺失地址数、重复数和错误数。
- 地址规范化、地图请求、地图状态和最终地址结果。
- 地址为空但未进入 Excel 的学校记录。

主 Agent 根据行政单位返回结果检查是否存在遗漏目录、重复任务、未完成复核、地址处理错误或未明确记录的覆盖缺口。

## Excel 格式

行政单位工作簿和城市工作簿统一使用 `query_city_core.excel_style`：

- 深蓝色表头、白色加粗微软雅黑字体。
- 数据字体统一为微软雅黑。
- 全部单元格水平和垂直居中。
- 冻结首行并启用列筛选。
- 关闭默认网格线。
- 地址列自动换行，数据行高由 Excel 自动适应。
- 信息来源保留可点击的 HTTP(S) 政府页面链接。
- 数据行不使用交替底色。

信息来源在工作簿中压缩为政府链接、本地文件名和原始行号，不展示完整的内部提取规则定位文本。

## 完成前验证

输出前检查：

1. `city_context.subdivisions` 中每个行政单位都有结果或明确的无来源状态，无遗漏和重复目录。
2. 幼儿园、小学、初中和高中均完成独立检索，覆盖状态与 `processing_status` 一致。
3. `government_source.json.items` 中每个来源都属于政府或教育行政部门，且本地文件存在。
4. 每个进入提取的来源均已完成规则复核；没有未批准规则被执行。
5. `address_records.json` 的 `stage` 为 `address_records`，`metrics.error_count` 为零。
6. `processed_address_records.json` 保留完整城市上下文，预期地图兜底时地图请求数不为零。
7. 每个行政单位分表行数等于该行政单位最终地址非空记录经过业务去重后的数量。
8. 城市总表行数等于所有行政单位分表行数之和。
9. 工作簿字段、工作表顺序、筛选、冻结、地址换行和来源超链接符合公共样式约定。
10. 工作簿能够正常打开，不存在明显乱码、截断或空表问题。

验证失败时修正原因并重新生成，不交付不完整结果。

## 失败处理原则

- 无法确认的学校类型、办学性质或地址保留空值或政府原文，不根据模型记忆补齐。
- 没有政府名录来源时明确写入 `no_official_source`，不得用地图或第三方学校库替代名录。
- 找到官方来源但文件无法使用时明确写入 `source_unusable`。
- 扫描来源没有视觉能力时，只能按 `no_vision_capability` 跳过，不运行本地 OCR。
- 单个来源解析失败时记录错误；`metrics.error_count` 非零时不得继续进入地址处理。
- 地图没有唯一合格候选时最终地址留空，不选择看起来最接近的结果。
- 缺少必要依赖、LibreOffice、地图密钥或输入输出文件无法读取、写入时停止并说明问题。
