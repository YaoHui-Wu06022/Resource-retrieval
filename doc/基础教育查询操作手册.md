# 基础教育查询操作手册

本文依据 [query-city-basic-education Skill](../.agents/skills/query-city-basic-education/SKILL.md) 整理，按实际执行顺序说明操作、判断规则和完成条件，供了解流程、执行检查和验收结果时使用。

## 一、任务目标与范围

输入一个中国城市，按该城市的直接下级行政单位查找政府公开的非高校学校名录，提取学校和地址，完成地址规范化及必要的地图补全，生成各行政单位工作簿和城市汇总 Excel。

- **行政范围**：使用城市组件返回的直接下级行政单位。具体可能是区、县、县级市或街道、镇，不能一律按“区”理解，也不继续向更低一级拆分检索。
- **学校范围**：幼儿园、小学、初中、高中四类必须独立检索；来源中出现的一贯制学校、完全中学、特殊教育学校、中职、技工和专门学校等也一并纳入。
- **资料来源**：采用政府或教育部门发布、实际包含学校名录的网页、附件或分页内容。地图用于后续地址补全，不用于编制学校名录；百科、择校网站等第三方资料不能作为名录来源。
- **结果边界**：结果反映本次政府资料的实际覆盖情况。没有找到可用来源，不等于该行政单位没有这类学校。

各行政单位工作簿包含“学校信息”和“异常校”两张表。城市总表汇总有效学校地址，并提供各行政单位的明细工作表。学校存在多个校区或被多个来源重复收录时，由脚本拆分和去重，原始名录条数不一定等于最终地址行数。

## 二、流程总览

确认运行条件 → 确认城市和行政单位 → 逐单位检索并保存政府名录 → 检查资料和处理扫描件 → 复核提取计划并预览 → 提取学校记录 → 串行处理地址 → 生成各单位工作簿和城市总表 → 验收交付。

按城市组件给出的行政单位顺序，逐单位完成来源检索到学校记录提取。全部单位完成后，再依次处理地址并生成工作簿；同一时间只能有一个地址处理进程。

Agent 负责来源是否可靠、学段是否覆盖及提取规则的复核；固定脚本负责读取资料、类型规范、去重、地址处理、排序和工作簿格式。这里的“批准提取规则”是 Agent 检查资料后的流程操作，不要求用户逐条批准。

## 三、分步操作

### 第 1 步：确认运行条件，建立本次任务目录

**操作：**

1. 确认用户要查询的城市。
2. 检查运行环境；尚未确认时先询问用户，确认后在本次任务执行过程中保持一致。
3. 检查网页、表格和 PDF 读取所需依赖，以及公共处理组件是否可用；处理 Word 时还需要 LibreOffice。
4. 检查高德地图密钥是否已配置。遇到必须解析的扫描件时，还需检查 MinerU 的访问凭据。
5. 为本次任务建立独立目录，按标准城市名、日期和时分秒保存，不覆盖以前的结果。

目录约定：`output/<标准城市名>/<YYYY-MM-DD>/Basic_Education/<HHMMSS>/`。后文的各行政单位目录均建立在此目录下。

**进入下一步的条件：** 用户已确认运行环境，当前所需依赖、密钥和公共组件可用。缺项时停止相应处理并说明，不自行安装依赖，也不编写一次性脚本复制固定流程。扫描件缺少 MinerU 凭据时，按第 5 步显式跳过该来源，不宣称已经完成解析。

### 第 2 步：确认标准城市名和直接下级行政单位

**操作：**

1. 使用城市组件取得标准城市名和直接下级行政单位清单。
2. 按清单中的原始名称建立同名目录，不自行增删、合并或改名。
3. 记录行政单位总数，作为最终目录和结果覆盖检查的基准。
4. 按清单顺序逐单位执行第 3～7 步。

**本步产物：** 标准城市信息、完整的行政单位清单和对应目录。

**进入下一步的条件：** 查询范围清楚，目录与清单一一对应。后续不能因为某单位资料难找而将其从任务范围中删除。

### 第 3 步：逐学段检索政府名录，检查时效与覆盖

**操作：**

1. 为当前行政单位分别检索幼儿园、小学、初中和高中名录，不因为找到一份综合资料就省略各学段检查。
2. 优先查找当年或上一年发布的资料，并按照下表依次检查发布层级。
3. 打开来源，确认正文、附件或分页中实际有学校名录。只有通知标题、政策说明或招生安排而没有名录的页面不能直接采用。
4. 判断名录是否覆盖当前行政单位及所需学段，并记录实际覆盖范围。
5. 优先采用网页表格、Excel、CSV、Word、可提取文字的 PDF；确认没有文本替代来源时，才采用扫描件并说明原因。

| 学段 | 检索与补查顺序 |
| --- | --- |
| 高中 | 市教育部门 → 市招考或中考平台 → 市数据平台。 |
| 幼儿园、小学、初中 | 区级教育部门 → 区级政府门户；缺位时继续检查市教育部门、市招考或中考平台、市数据平台。 |

上表中的区级指当前直接下级行政单位对应的主管部门或政府门户。查不到来源时不能省略后续层级，必须完成该学段规定的补查。

**跨区域与旧资料的处理：**

- 市级名录有“校址所在区”等可用于归属判断的字段时，按当前行政单位过滤后采用。
- 市级名录没有可拆分的行政归属信息时，不能将整张表归到某一个单位；记录原因，并继续寻找区级或可拆分的来源。
- 超过两年的名录，必须再次核查当年和上一年资料；确实没有更新来源时，可以保留，但只能按部分覆盖记录。
- 发布日期无法确认时保留为空，不把下载日期当作来源发布日期。

**一贯制和完全中学的学段覆盖：**

| 官方明确的学校类型 | 可计入的学段覆盖 |
| --- | --- |
| 完全中学 | 初中、高中。 |
| 九年一贯制 | 小学、初中。 |
| 十二年一贯制 | 小学、初中、高中。 |
| 十五年一贯制 | 幼儿园、小学、初中、高中。 |

上述映射必须有来源中的官方类型说明或明确标记，不能仅凭学校名称猜测。发现这类学校可以补充对应学段的覆盖依据，但仍需完成四类学段各自的检索与检查。

**覆盖结论：**

| 结论 | 适用情况 |
| --- | --- |
| 已覆盖 | 已有可用来源覆盖该学段。 |
| 部分覆盖 | 已有可用资料，但时效或范围仍存在缺口。 |
| 无官方来源 | 完成规定层级补查后，仍未找到可采用的官方名录。 |
| 来源不可用 | 找到官方资料，但完成访问和可用性检查后仍无法用于提取，且没有可用替代来源。 |

任何未达到“已覆盖”的学段，都要写明“核验了哪些层级、得出什么结论”。网页访问失败不能直接等同于无官方来源；无来源和来源不可用也不表示当地不存在相应学校。

### 第 4 步：保存来源和相关详情页

**操作：**

1. 对政府栏目页先筛选候选链接，逐项复核后再决定采用，不能把候选链接直接当成已确认来源。
2. 使用固定下载流程保存实际包含名录的正文或附件，保留来源标题、发布部门、发布日期、说明页网址和实际内容网址。
3. 名录分布在多个分页或结构相同的学校详情页时，采集全部相关页面，登记在同一来源下，并保留每页网址。
4. 来源是压缩包时保留原件，通过既有流程解出可读取文件，再从中选择实际名录；解压失败要记录并处理。
5. 检查保存的文件是否可读，是否与网页所指的名录一致。
6. 为当前单位登记一份政府来源清单，记录实际采用的本地文件、覆盖学段、是否含地址，以及必要的缺口说明。

访问时先采用直接请求及备用直连方式，并记录尝试；确实需要网页脚本或登录时再使用浏览器，同样记录结果。同一网站默认串行访问。

**本步产物：** 政府来源清单、本地原始资料及访问记录。仅收录已经确认采用并保存的来源，未采用候选和不含名录的通知不进入清单。

**进入下一步的条件：** 来源可追溯、文件可读取、学段覆盖结论有依据。无可用来源的行政单位也要保留明确状态和补查记录，不能伪造学校记录继续提取。

### 第 5 步：检查资料结构，按需解析扫描件

**操作：**

1. 运行资料检查流程，识别网页表格、工作表或文档中的名录区域，生成待复核的提取计划。
2. 查看自动识别的表头、校名列、地址列和学校类型。自动识别结果只是初稿，需要结合原文检查。
3. 单一学校类型且没有类型列的来源，可以预填统一类型；混合多个学段的来源不能直接给整表套用一个类型。
4. 校名含有“九年一贯制”等官方明确标记时，可以据此判型；没有明确依据时不能猜测。

**确需使用扫描件时：**

1. 确认已经核查文本替代来源，并登记“没有文本替代”的原因。
2. 利用逐页摘要定位含名录的页面，尤其是篇幅较长的报考指南。
3. 使用既有 MinerU 流程转录所需页面，保留原始行列关系，不添加原文没有的地址。
4. 将生成的视觉解析文件登记到对应来源，供后续规则复核和提取使用。
5. 检查表格内容是否完整，特别是跨页表头、合并单元格、行政单位列和地址列。

没有 MinerU 凭据时，显式记录“缺少视觉解析能力”并跳过该扫描来源。不伪造视觉文件，也不改用本地 OCR 替代。跳过造成的学段缺口要同步反映到覆盖说明中。

**进入下一步的条件：** 可用资料已形成提取计划；需视觉解析的来源已有登记的解析结果，或已明确记录跳过及其影响。

### 第 6 步：复核提取规则，预览行覆盖

**操作：**

1. 对照原始资料，确认要读取的文件、工作表、网页表格或 PDF 页码。
2. 核对学校名称、地址、类型、办学性质等列的位置，避免将联系电话、招生范围或报名地点当作学校地址。
3. 检查固定值是否适用于全部选中记录；需要继承上一行行政单位或类别的合并单元格，按原表关系设置向下填充。
4. 明确排除重复表头、合计、注释和无关行，不通过排除真实学校行消除检查报错。
5. 对跨区名录设置当前单位筛选条件；报考指南只保留确实含当前单位单元格的相关页面或表格规则。
6. 由 Agent 完成复核配置，并使用固定复核脚本批准提取规则。
7. 批准后执行预览，检查将提取的行、类型分布、遗漏、重叠和未批准规则。

**进入下一步的条件：** 预览结果为 **0 缺行、0 重叠、0 待批准**。任何一项非零都要返回规则和原文修正，再重新预览。批准完成不能代替预览，也不能手工抄写最终记录绕过规则检查。

### 第 7 步：提取学校记录，核对内容与错误

**操作：**

1. 根据已批准且预览通过的计划提取学校记录。
2. 检查记录是否包含学校名称、原始地址、学校类型、办学性质、发布日期、行政单位和可定位的政府来源。
3. 来源未提供地址时保留为空，交给下一步按规则补全，不根据常识或学校名称编造地址。
4. 由脚本按学校名称和原始地址合并重复记录，并按学段规则去重，保留官方类型标签。例如同校同时出现在小学和九年一贯制名录时，保留更完整的官方类型。
5. 来源明确列出多个校区地址时由脚本拆分；无法唯一确定校区与地址对应关系的，保留歧义说明，不强行配对。
6. 查看提取结果状态和错误统计，确认输出已到达待处理地址阶段，错误数为 0。

**本步产物：** 当前行政单位的学校原始地址记录。

**进入下一步的条件：** 提取无错误，行政单位和来源可追溯。按顺序完成其余行政单位的第 3～7 步后，再统一进入地址处理；无可用来源的单位保留状态和原因，不能在最终验收中消失。

### 第 8 步：串行处理地址，保留异常

**操作：**

1. 依次处理各行政单位的地址，同一时间仅运行一个地址处理进程。
2. 清洗地址表达，核对目标城市及行政单位归属。
3. 按政府资料中的地址完整程度，决定直接采用还是在所在行政单位内按校名检索地图地点。
4. 查看地址处理结果及异常原因，保留没有获得合格地址的记录，供复检和异常表使用。

| 政府资料中的地址情况 | 处理原则 |
| --- | --- |
| 完整有效地址 | 直接采用政府地址。 |
| 已包含小区、楼栋、村等具体地点 | 按规则采用政府地址，不仅因缺少道路门牌就认定无效。 |
| 地址为空，或仅有区、街道、片区且没有具体地点 | 按学校名称在所在行政单位内进行地图补全。 |
| 地图找到符合规则的结果 | 采用地图地址，保留真实获取方式。 |
| 目标城市或行政归属冲突，或没有合格补全结果 | 最终地址留空，记录异常原因并保留原始证据。 |

地图地点必须符合名称和行政归属等匹配要求，不能只因名称相近就采用。原始资料中的空地址允许进入本步处理，处理失败也不能通过删除记录掩盖。

**进入下一步的条件：** 各有提取记录单位的地址处理已完成，结果文件合法，错误和冲突已经查看并有明确处置。不能把未执行地址处理的原始记录直接当成最终结果。

### 第 9 步：生成各单位工作簿和城市总表，完成验收

**操作：**

1. 使用各行政单位的地址处理结果生成工作簿，去重、排序、列序和格式均由脚本完成，不手工调整成表结果。
2. 检查各单位工作簿中的“学校信息”：仅收录最终地址非空且不存在校区地址配对歧义的记录。
3. 检查各单位工作簿中的“异常校”：保留最终地址为空或校区地址配对存在歧义的记录，异常原因不能为空。
4. 检查城市总表的“学校信息”汇总页和各行政单位明细页；按有效地址行数核对，城市汇总页行数应等于各单位“学校信息”行数之和。
5. 空地址记录保留在地址处理文件和各单位“异常校”中，不进入城市有效地址汇总。城市总表不能代替逐单位异常复核。
6. 将实际生成结果的单位与完整行政单位清单核对；没有可用来源的单位应有明确状态和原因，不能仅凭生成器成功就认定全市覆盖完成。
7. 重新打开工作簿，检查工作表、地址、来源及行数，确认文件可正常读取。

**完成检查清单：**

- [ ] 运行环境已经用户确认，本次执行保持一致。
- [ ] 所有直接下级行政单位均有结果或明确无可用来源状态，目录不重不漏。
- [ ] 幼儿园、小学、初中、高中均完成独立检索及规定层级补查。
- [ ] 未完全覆盖的学段均有“已核验层级 + 结论”，旧资料和扫描件采用原因明确。
- [ ] 采用来源已保存，分页、详情页及附件可追溯。
- [ ] 人工配置的提取计划已预览，缺行、重叠和待批准均为 0。
- [ ] 扫描来源已登记视觉解析文件，或显式记录因缺少能力而跳过。
- [ ] 各有数据单位的原始地址和处理结果合法，地址处理按串行完成。
- [ ] 各单位工作簿双表齐全，异常原因非空，歧义记录未混入有效结果。
- [ ] 城市有效地址行数等于各单位有效地址行数之和，文件可正常打开。

完成后向用户提供：标准城市名、行政单位总数及各状态数量、来源总数、最终地址行数，以及最终文件绝对路径。逐单位检索与复核证据保留在本次任务目录中。

## 四、遇到问题时回到哪一步

| 问题 | 返回位置与处理方式 |
| --- | --- |
| 运行环境尚未确认 | 第 1 步：先询问用户，不预设具体环境。 |
| 某类学校未找到名录 | 第 3 步：补齐规定层级检索，再记录结论，不能解释为当地没有学校。 |
| 只有旧名录或扫描件 | 第 3 步：再查近期或文本替代来源，确认没有后记录限制。 |
| 网站打不开、附件下载失败 | 第 4 步：检查并记录访问尝试，不能直接标为无官方来源。 |
| 市级名录无法按行政单位拆分 | 第 3～4 步：继续找可拆分来源，不能把全市学校放入一个单位。 |
| 扫描件缺少解析凭据 | 第 5 步：明确跳过该来源并记录缺口，不生成虚假解析结果。 |
| 预览存在缺行、重叠或未批准规则 | 第 6 步：对照原表修正规则，重新预览。 |
| 提取出现错误、类型或地址列错位 | 第 6～7 步：修正定位与规则，再重新提取。 |
| 地址为空、跨区冲突或地图无法匹配 | 第 8 步：按规则核验，保留原记录和异常原因。 |
| 城市行数与各单位不一致，或有单位缺失 | 第 9 步：检查输入结果和单位覆盖，修正后重新生成。 |
