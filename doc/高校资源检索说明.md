## 目标

根据用户输入的中国城市，从项目内置的全国普通高等学校名单中筛选该城市的高校，补充院校标签和办学性质，并检索学校官网中的地址与校区信息。

学校官网是地址和校区名称的事实来源。地图用于验证官网地址；官网未取得地址时，可以根据已经确认的学校或校区名称进行受限兜底。地图不得改写官网已经明确提供的地址，兜底结果必须明确标记。

## 输入

接受一个中国城市名称，例如：

- 广州市
- 广州

如果用户没有提供城市，先询问城市名称。运行前还需要确认用户希望使用的 Python 环境；已经确认过的环境无需重复询问。

## 输入文件

高校名单、985 名单和 211 名单固定使用本项目高校检索 Skill 内置的文件，不从当前工作目录临时查找。

缺少名单文件或必要运行依赖时，停止处理并说明缺项，不自行安装。

## 输出文件

全部文件写入：

`<项目根目录>/output/<标准城市名>/<YYYY-MM-DD>/Higher_Education/`

最终文件名为：

`高校建筑查询_<标准城市名>_<YYYY-MM-DD>.xlsx`

例如：

`E:\DSH\output\广州市\2026-08-27\Higher_Education\高校建筑查询_广州市_2026-08-27.xlsx`

最终工作簿只包含一个“高校信息”工作表。地址为空的地点不进入最终工作簿，但其检索过程仍保留在中间记录中。

## 主表字段

“高校信息”工作表按以下顺序输出：

| 字段 | 内容 |
| --- | --- |
| 序号 | 按最终输出结果重新编号 |
| 学校名称 | 学校名称；校区明确时为学校名称加校区名称 |
| 主管部门 | 教育部名单 |
| 办学层次 | 教育部名单 |
| 院校标签 | 985、211 或空值 |
| 办学性质 | 公办、民办、中外合作、境外机构或待核验 |
| 最终地址 | 官网规范地址或地图兜底地址 |
| 地址获取方式 | 官网提取或地图兜底 |
| 查询日期 | 工作簿生成当天的日期，格式为 YYYY-MM-DD |
| 信息来源 | 实际检索和支持判断的学校官方页面 |

## 第一步：标准化城市名称

按照以下顺序处理：

1. 使用项目内置的中国城市名称资产进行精确匹配。
2. 如果没有精确匹配且输入不以“市”结尾，只尝试补充一个“市”字。
3. 匹配成功后使用标准城市名进行名单筛选和目录命名。
4. 无法匹配时停止并要求用户提供明确城市，不使用包含匹配或主观猜测。

例如，`广州`标准化为`广州市`。

## 第二步：读取教育部名单

读取高校名单时根据字段名称定位表头，不假定表头位于固定行。

需要识别的字段包括：

- 序号
- 学校名称
- 学校标识码
- 主管部门
- 所在地
- 办学层次
- 备注

标题行、地区分组行、空行及缺少有效学校名称或学校标识码的行不作为学校记录。学校标识码按文本保留，避免科学计数法或前导内容丢失。

## 第三步：筛选学校

只保留“所在地”与标准城市名完全一致的学校。

筛选结果必须至少包含一所学校，且学校标识码不得重复；否则停止并说明名单或城市输入问题。

## 第四步：判定院校标签

只有办学层次为“本科”的学校参与 985、211 名单匹配，学校名称采用完全匹配。

判定顺序为：

1. 命中 985 名单，标记为“985”。
2. 未命中 985、但命中 211 名单，标记为“211”。
3. 其余学校留空。

985 优先于 211；专科院校不填写这两类标签。

## 第五步：判定办学性质

根据教育部名单“备注”按以下优先级判断：

1. 包含“中外合作办学”或“内地与港澳合作办学”：中外合作。
2. 包含“境外高等教育机构”：境外机构。
3. 包含“民办”：民办。
4. 备注为空：公办。
5. 备注非空但未命中以上规则：待核验，并保留警告原因。

## 第六步：查找学校官网

每所学校只进行一次 Web Search，查询词同时包含学校全名、官网、校区和地址。可以比较同一次搜索返回的多个候选，也可以保留其中已经确认的官网地址页或校区页作为后续候选，不得为更换域名再次搜索。

确认官网时：

- 页面标题、站点名称或正文应当明确对应学校全名。
- 优先使用可访问的学校主站，`.edu.cn` 不是硬性条件。
- 主站不可访问时，可以采用同次搜索中归属明确的其他官方域名。
- 招生平台、百科、媒体、自媒体、地图页面和第三方院校库不能作为学校官网。
- 页面跳转到新域名时，需要重新确认新域名确属该校。

如果同次搜索已经明确证明学校合并或停止独立办学，记录原因和官方证据，不再抓取页面，也不进入地图兜底。

## 第七步：页面抓取

每次只抓取一所学校的一个官方页面。抓取完成后先审查以下内容，再决定是否继续：

- 请求地址和最终地址是否仍属于已确认的官网。
- 页面是否正常访问。
- 提取到的地址候选及其邻近上下文。
- 页面明确出现的校区名称。
- 指向联系方式、地址、校区、校园分布、学校概况等页面的同域链接。

页面抓取先使用公共地址提取能力识别正文和页脚中的地址信息，再由高校层识别校区名称及地址与校区的对应关系。完整页面内容仅在本地处理，不整体输出到上下文中。

无标签的页脚裸地址、新闻标题或宣传文本不强行当作有效地址。页面明确给出“地址”或校区与地址关系时，才形成官网地址候选；只有校区名称而没有地址时，保留为校区线索，供后续页面检索或地图兜底使用。

## 第八步：官网访问顺序

访问顺序如下：

1. 先抓取官网首页，并重点检查页脚。
2. 信息不足时，从同次搜索已确认的官网页面或当前页面的同域链接中选择下一页。
3. 优先选择联系方式或地址页，其次是校区汇总或详情页、学校导游或校园分布页、学校章程、学校概况或简介页。
4. 每次后续抓取都必须在审查上一页结果后单独决定，不批量遍历网站。

通常每所学校最多抓取三个页面，访问失败也计入页数。只有校区汇总页明确列出多个校区详情链接、但没有给出完整地址时，才可以继续访问尚未取得地址的校区详情页；每个明确校区最多增加一个详情页，全校最多八页。

满足以下任一条件时停止：

- 已取得明确地址，且没有未解决的校区线索或其他高价值校区链接。
- 普通三页预算用尽，或符合校区详情扩展条件时八页预算用尽。
- 剩余链接均非同域，或与地址、校区无关。

不得遍历新闻、招生简章、院系列表、网站地图或大量二级页面。

## 第九步：提取与确定地址

### 官网地址

提取官网地址时：

- 保留省、市、区县、道路、门牌号和建筑等实际地址内容。
- 删除电话、传真、邮箱、邮政编码、版权和备案信息等其他字段。
- 只补充地址规范化所需、且能够由标准城市及行政区关系确定的行政区表达。
- 不补写官网没有提供的道路或门牌号。
- 信息来源使用实际取得该地址或校区线索的官方页面。

### 地图验证

使用高德地图服务处理地址，运行环境需要提供有效的 `AMAP_KEY`，并统一限速，避免并发超限。

官网地址完整时，地图只进行交叉验证。无论地图结果一致、部分一致、未找到或发生冲突，最终地址仍采用官网规范地址，地图不得补全或覆盖官网地址。

### 地址兜底

官网检索停止后仍没有地址时，可以使用已经取得的学校名称或明确校区名称进行地图兜底。兜底结果必须同时满足：

1. 机构名称能够明确对应目标学校或校区。
2. 地址明确位于标准城市。
3. 返回的是可用地址，不是省、市或区级泛化结果。
4. 不存在多个无法区分的同名候选。

满足条件时使用地图地址，并在“地址获取方式”中标记为“地图兜底”；不满足条件时最终地址留空。

### 最终地址判定

最终地址按以下顺序确定：

1. 官网地址完整：采用官网规范地址。
2. 官网没有地址且地图唯一兜底成功：采用地图地址。
3. 地址指向目标城市外、规范化存在冲突或没有合格兜底结果：留空。

## 第十步：多校区处理

### 只有一个地址

官网只给出一个地址且没有明确校区名时，以学校名称作为地点名称，不补写“校本部”。

### 多个明确校区

官网明确给出多个“校区名称 + 地址”时，每个校区形成一条地点记录，名称使用“学校名称 + 校区名称”。

只保留能够确认位于输入城市的校区。不得根据区县、道路或常识反推校区名称。

### 地址包含校区名称

地址写成“具体地址（某校区）”或在地址邻近位置明确标注校区时，保留该对应关系。地址与校区必须依据同一局部上下文绑定，不能把相邻但不相关的校区和地址反向关联。

### 同一校区存在别名

同一校区在官网不同位置使用多个名称时，以官网首页页脚随地址明确标注的名称为准；其他同址名称只作为别名线索，不重复生成记录。

### 有地址但没有校区名称

保留地址，以学校名称作为地点名称，不填写或猜测校区名称。

### 只有校区名称但没有地址

保留“学校名称 + 校区名称”作为地图检索地点。只有地图唯一兜底成功后才进入最终工作簿。

### 去重

相同校区和相同地址只保留一条。不同校区不得仅因地址文字相似而合并；同一明确校区出现多个不同官网地址时保留警告，等待核验。

## 过程记录

检索过程中保留：

- 城市筛选后的高校基础信息。
- 每所学校的处理状态及按访问顺序保存的页面结果。
- 官网地址候选、校区线索、页面来源和访问警告。
- 地址规范化、地图验证或兜底结果及统计信息。
- 已确认合并或停止独立办学学校的原因和证据链接。

页面访问失败但未确认学校合并或停止独立办学时，仍按正常检索对象保留失败页面，不擅自跳过学校。

## Excel 格式

最终工作簿：

- 只包含“高校信息”工作表。
- 只输出最终地址非空的地点。
- 表头加粗并设置底色，冻结首行并启用筛选。
- 学校名称、最终地址和信息来源按内容设置合理列宽。
- 信息来源保留完整、可点击的 HTTP(S) 官方页面链接。
- 不创建查询日志或异常信息工作表。

## 完成前验证

输出前检查：

1. 基础名单完整覆盖标准城市中的学校，学校标识码无重复。
2. 每所学校均已记录为正常处理、合并或停止独立办学，不得遗漏。
3. 每所学校只进行一次 Web Search；页面数符合通常三页、特殊校区扩展最多八页的规则。
4. 所有页面均属于已经确认的学校官方域名。
5. 本科院校的 985、211 标签和所有学校的办学性质符合名单规则。
6. 官网地址与地图地址没有互相覆盖；地图兜底记录已明确标记。
7. 公共地址处理不存在未处理的地图错误；预期调用地图时，地图请求数不能为零。
8. 最终工作簿只有十个规定字段和一个“高校信息”工作表，每行最终地址非空；查询日期格式为 YYYY-MM-DD。
9. 工作簿能够正常打开，不存在明显乱码、截断或空表问题。

验证失败时修正原因并重新生成，不交付不完整结果。

## 失败处理原则

- 无法确认的信息留空，不根据模型记忆或第三方网站补齐。
- 单个官网访问失败时继续处理其他学校，并保留失败页面和原因。
- 学校合并或停止独立办学只能依据明确证据判断。
- 缺少必要依赖、浏览器、地图密钥或名单文件，以及输入输出文件无法读取或写入时，停止并说明问题。

## 最终回复

完成后只向用户说明：

- 标准城市名。
- 基础名单学校数量。
- 公共地址处理状态计数。
- 最终地址行数。
- 最终文件绝对路径。

不展开逐校搜索过程，详细证据保留在任务输出目录中。
