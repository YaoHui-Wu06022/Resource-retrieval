# 高校查询操作手册

本文依据 [query-city-universities Skill](../.agents/skills/query-city-universities/SKILL.md) 整理，按实际执行顺序说明每一步的操作、判断规则和完成条件，供了解流程、执行检查和验收结果时使用。

## 一、任务目标与范围

输入一个中国城市，筛选该市普通高校，查找学校官网公开的校区地址，完成地址规范化和必要的地图核验、补全，最终生成 Excel 工作簿。

- **学校范围**：以 Skill 自带的教育部普通高校名单为准，按名单中的“所在地”筛选目标城市。不是通过网络搜索重新编制全国高校名单，也不会自动纳入名单所在地为外市的高校在本市设立的校区。
- **地址范围**：在入选高校中查找属于目标城市的校区地址，市外地址不作为本市有效结果。
- **资料来源**：固定高校名单提供学校基础信息；学校官网网页提供校区与地址证据；高德地图用于必要的核验和补全。不使用 PDF、百科或第三方院校库补充校区地址。
- **结果粒度**：一所学校可以对应多条校区或不同物理地址记录，因此最终地址行数不一定等于学校数。

最终工作簿包含“高校信息”和“异常校”两张表。前者收录最终地址非空的记录，后者保留最终地址为空的记录并说明原因。

## 二、流程总览

确认运行条件 → 确认城市与生成名录 → 逐校确认官网 → 探测并复核官网 → 抓取官网页面 → 合并并核对学校覆盖 → 整理校区地址 → 规范化与地图处理 → 生成工作簿并验收。

执行中，Agent 负责官网身份、学校合并或停办等证据判断，以及异常复核；固定脚本负责筛选、探测、抓取、保存、合并、地址处理和生成工作簿。单校抓取结果只能由既有抓取运行器写出或替换，不能手工改写为“成功”。

## 三、分步操作

### 第 1 步：确认运行条件，建立本次任务目录

**操作：**

1. 确认用户要查询的城市。
2. 检查运行环境；尚未确认时先询问用户，确认后在本次任务执行过程中保持一致。
3. 检查 Excel 处理依赖、网页抓取依赖及 Chromium 浏览器是否可用。
4. 检查固定资产是否齐全，包括普通高校名单、985 名单和 211 名单。
5. 检查高德地图密钥是否已配置。密钥从环境变量或项目配置文件读取，不写入结果文档。
6. 为本次任务新建独立输出目录。目录按“标准城市名 / 日期 / 高校类别 / 时分秒”组织，不覆盖以前的任务。

目录约定：`output/<标准城市名>/<YYYY-MM-DD>/Higher_Education/<HHMMSS>/`。后文提到的过程文件均保存在本次目录内。

**进入下一步的条件：** 环境、依赖、浏览器、地图密钥和名单资产均可用。缺少任一项时停止并说明，不自行安装或编写临时替代流程。

### 第 2 步：确认标准城市名，生成高校名录

**操作：**

1. 将用户输入转换为标准城市名，并取得该城市的直接下级行政单位，供后续核对地址归属。
2. 从固定的普通高校名单中筛选“所在地”等于标准城市名的学校。
3. 保留学校名称、学校标识码、主管部门、办学层次等基础信息。
4. 根据固定的 985、211 名单补充院校标签；同一学校同时符合时，标签优先显示 985。
5. 根据原始名单备注归类办学性质，对无法按规则归类的记录保留待核验提示。
6. 记录名录学校总数，作为后续所有学校覆盖检查的基准。

**本步产物：** 城市信息，以及城市高校名录的 Excel 和过程数据文件。

**进入下一步的条件：** 城市范围明确，名录已生成，学校数及待核验提示已查看。后续不能因为某校难以检索而从名录中删除它。

### 第 3 步：逐校搜索并确认官网

**操作：**

1. 将名录分批，每批不超过 20 所学校。
2. 每校先搜索一次，关键词采用“学校全名 + 官网 + 校区 + 地址”。同一次搜索也检查合并、停止独立办学或无官网的官方证据。
3. 根据页面标题、站点名称和正文核对是否确实属于该校，优先选用可访问的学校主站。域名不强制要求以 `.edu.cn` 结尾。
4. 记录确认的官网及允许访问的官方域名；同时保留最多 3 个相关候选页面，例如校区介绍、学校概况、联系方式。
5. 候选页面必须属于已经确认的官方域名。招生信息站、百科、第三方院校库及地图页面不能作为学校官网。

每所学校必须形成下列一种结论：

| 判断结果 | 操作要求 |
| --- | --- |
| 已确认官网 | 保存主页、官方域名及可选的候选页面，准备抓取。 |
| 有官方证据支持无官网 | 保存证据链接和具体原因，后续尝试按学校名称从地图补全。 |
| 已合并或停止独立办学 | 保存官方证据及跳过原因，后续不抓取官网。 |
| 暂时无法判断 | 记录失败原因，进入统一复检。 |

**判断边界：** “没搜到”“网页打不开”都不足以直接认定无官网，也不能作为学校已合并或停办的依据。不要为了更换域名在初次确认阶段反复搜索。

**本步产物：** 各批次官网确认记录，每所学校均有明确结论或待复检原因。

### 第 4 步：探测官网，统一复检后汇总

**操作：**

1. 对已确认官网的学校逐一访问主页，检查可达性、跳转后的网址、最终页面标题及学校身份是否匹配。此项访问探测不占用网页搜索次数。
2. 如果主页跳转到尚未确认的域名，核对最终页面的学校身份及官方证据。确认归属后，补入该域名，并将主页更新为最终网址。
3. 对主页失败、身份不明确或仍无结论的学校统一复检一次，可重新搜索并修正对应批次。
4. 重新汇总全部批次，形成完整的官方域名清单。

**进入下一步的条件：** 每所学校恰好对应一条官网确认记录，探测报告已复核，不再存在未解决的确认失败。统一复检后仍无法判断的，停止并说明，不进入抓取阶段。

### 第 5 步：抓取官网页面，检查校区覆盖

**操作：**

1. 使用固定抓取运行器读取官方域名清单，默认同时处理 3 所学校。
2. 对普通学校先访问主页并检查学校身份。首页标题不含学校名称时会产生告警，需要查看其是否确实为该校网站。
3. 如果已提供候选页面，即使首页找到地址，也继续抓取全部候选页面。
4. 在页面额度内，继续查看已确认域名中的相关链接，优先关注校区详情，再查看学校层面的概况、简介、章程、地址和联系我们页面。
5. 不跟随“产业学院简介”“队伍概况”等与学校整体地址无关的栏目。同一校区详情只补抓一次，相同主机名和路径的链接去重。
6. 有证据支持无官网，以及合并或停办的学校，由运行器直接保存相应结果，不启动浏览器抓取。

**页面额度：**

- 默认每所学校最多访问 3 页，访问失败的页面也占额度。
- 提供了候选页面，或发现多个校区的汇总线索时，可以放宽至最多 6 页。
- 多校区线索包括至少 2 个校区提示或链接，或同一页面出现至少 2 个不同物理地址。

**重点复核：**

| 报告情况 | 如何处理 |
| --- | --- |
| 某校区详情页未抓，但其他已抓页面已有该校区地址 | 作为信息提示，不直接认定校区地址遗漏。 |
| 某校区详情页未抓，且所有已抓页面均没有该校区地址 | 作为真实覆盖缺口复核，在规则和页面额度内补充官方候选页或调整抓取入口。 |
| 学校抓取失败 | 查看原因，必要时更新清单，仅针对失败学校统一复检一次。 |

复检后仍失败的学校会阻止进入合并。对官网确实未公开的校区地址，应记录“官网未公开”，不能用第三方地址填补后宣称官网已经覆盖。

**本步产物：** 每校一份原始抓取结果，以及抓取报告和失败清单。页面内容及失败页由运行器原样保留。

### 第 6 步：合并学校结果，检查是否遗漏

**操作：**

1. 合并全部单校结果。
2. 核对单校文件与名录中的学校标识是否一致，检查是否重名覆盖、重复处理或缺失。
3. 检查每所学校均处于允许的结果状态：完成抓取、依据证据跳过，或依据证据确认无官网。
4. 检查每校抓取页数是否符合默认或扩展额度。
5. 核对学校数量关系：**名录学校数 = 完成抓取学校数 + 跳过学校数 + 无官网学校数**，遗漏数必须为 0。

**进入下一步的条件：** 所有学校均被覆盖，文件和状态校验通过，没有用删除失败学校的方式凑齐结果。

### 第 7 步：提取、清洗并整理校区地址

**操作：**

1. 从已抓取的官网页面中提取校区名称与地址，保留对应来源页面，形成可追溯的候选地址记录。
2. 根据页面证据关联校区和地址，避免将学校概况中的多校区枚举错误配对。
3. 清理地址中的电话、传真、邮箱、邮编等联系信息，以及混入的学校名称尾缀、房间号等噪音。
4. 排除纯机构名、费用文字、方向距离描述及校区职责叙述。例如“东行 4 千米”“主要承担本科教育任务”不能单独生成地址行。
5. 合并同一物理地址的书写变体。同校多条地址没有校区名称时，只要属于不同物理地址，就分别保留，不强行压缩为一条。
6. 检查同校同路重复：已有带门牌地址时，不再保留同路的无门牌变体。
7. 无官网学校保留一条空地址记录，并附官方证据和原因，交给下一步尝试地图补全。

**本步产物：** 清洗后的待处理地址记录和页面提取结果，供统一地址处理组件使用。

**进入下一步的条件：** 地址与学校、校区的关联有依据，来源可追溯，非地址文本已排除，学校处理数量仍与名录一致。

### 第 8 步：规范化地址，完成地图处理与复核

**操作：**

1. 将地址清洗为统一表达，核对城市和直接下级行政单位，尽量整理为“城市名 + 下级行政单位 + 具体位置”。
2. 排除指向市外的地址，识别行政区归属等规范化冲突。
3. 运行统一地址处理流程，根据官网地址的完整程度执行必要的地图核验或补全。
4. 查看处理状态、地图请求统计及错误，逐条复核标为“部分匹配·待复核”的记录。

**最终地址的取舍：**

| 情况 | 处理原则 |
| --- | --- |
| 官网地址完整有效 | 优先采用官网地址，不因为地图给出另一条地址就直接替换。 |
| 官网地址缺少下级行政单位等内容 | 地图结果须有道路、门牌等共同证据，才能据此补全；不能只凭校名相近采用。 |
| 官网未提供地址，或有证据支持无官网 | 按学校名称检索地图地点，符合唯一匹配及城市归属等要求时采用地图地址。 |
| 有官网地址，但地图无法确证 | 按待复核规则保留官网地址，不填入无关地点；缺少必要位置内容、无法形成合格地址的记录仍留空。 |
| 地址指向市外、存在规范化冲突，或没有地址且地图无法合格补全 | 最终地址留空，保留原因。 |

地图补全不得误用附近公交站、地铁站等辅助地点。官网没有公开的地址即使通过地图补全，也应保留真实来源，不标为官网提取。

地图处理不等于每一行都必须发起地图请求：当前公共组件对结构完整且有可核验具体位置的地址允许直接采用。对本应调用地图的记录，请求数不得为 0；地图错误必须处理，不能把未完成地图处理的结果当作完整结果。

**进入下一步的条件：** 地址处理已完成，没有遗留的地图调用错误，所有待复核记录均已逐条查看并按证据处理。

### 第 9 步：生成 Excel，完成交付检查

**操作：**

1. 使用地址处理结果生成最终工作簿，文件名为 `高校建筑查询_<标准城市名>_<YYYY-MM-DD>.xlsx`。
2. 检查“高校信息”表，共 11 列，只收录最终地址非空的记录。
3. 检查“异常校”表，共 9 列，覆盖最终地址为空的记录，包括无官网且地图未能补全的学校；异常原因不能为空。
4. 检查生成器的发布前质量检查结果：地址不能残留电话、邮箱等联系词，不能存在同校同路“有门牌与无门牌”并存的重复行。
5. 如果质量检查拦截结果，逐条追查来源，补充官方候选页面或调整确认批次，再运行受影响步骤。不得跳过检查直接交付。
6. 重新打开工作簿，核对工作表、列数和行数，确认文件可正常读取。

**完成检查清单：**

- [ ] 官网确认记录与名录一一对应，跳转和身份问题已复核。
- [ ] 域名确认和抓取失败均按规则统一复检，未遗留阻断问题。
- [ ] 每校结果齐全，无重复、无遗漏，页面额度符合规定。
- [ ] 多校区覆盖已检查，官网未公开的地址已如实说明。
- [ ] 不同物理地址得到保留，地址噪音和同路重复已清理。
- [ ] 地址处理完成，地图错误已处理，待复核记录已逐条检查。
- [ ] 工作簿通过发布前质量检查，可以正常打开，两张表符合收录规则。

完成后向用户提供：标准城市名、名录学校数、域名与抓取状态计数、地址处理状态计数、最终地址行数，以及最终 Excel 的绝对路径。逐校检索证据和过程保留在任务目录中。

## 四、遇到问题时回到哪一步

| 问题 | 返回位置与处理方式 |
| --- | --- |
| 依赖、浏览器、密钥或名单缺失 | 第 1 步：停止说明，待运行条件补齐。 |
| 官网身份不明、跳转或无法访问 | 第 3～4 步：查看官方证据，按统一复检规则更新确认记录。 |
| 页面抓取失败 | 第 5 步：查看失败清单，更新入口后仅复检失败学校一次；仍失败则停止。 |
| 校区地址可能遗漏 | 第 5 步：先检查其他已抓页面是否已有地址，再判断是否需要补抓。 |
| 学校数量对不上 | 第 6 步：按名录逐校检查，不通过删除学校或手工伪造结果解决。 |
| 地址混入联系信息、校区配错或重复 | 第 7 步：追溯官网原文及校区关联，必要时返回抓取环节补证据。 |
| 地图结果不匹配、地址属外市或调用报错 | 第 8 步：核对归属和匹配证据；处理调用错误；无合格地址则留空并说明。 |
| 工作簿生成被质量检查拦截 | 第 9 步定位问题，回到相关来源或地址步骤修正后重新生成。 |
