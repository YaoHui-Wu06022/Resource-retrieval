# 医疗机构检索实现设计（草案）

## 1. 目标与范围

按中国城市检索政府公开的“有执业许可”的医疗机构名单，覆盖医院、
诊所、门诊部、社区卫生服务中心/站、村卫生室等，统一规范地址，
必要时以高德兜底，生成机构信息 Excel。主表只要求三个业务字段：
机构名称、地址、机构级别（三级/二级/一级）；机构类别由于与名称、
级别同表可直接获得，保留为筛选列，其余来源属性仅用于内部去重与
溯源，不要求全量拿到。与基础教育一样，名单必须是官方发证/公示名单，
不采用第三方机构库。

典型来源（广州市）：

- 市卫生健康委“医疗机构查询”栏目：
  <https://wjw.gz.gov.cn/fwcx/yljgcx/>；
- 每期固定三份表格：省卫生健康委员会发证、省中医药局发证、
  市卫生健康委员会发证，正文页配同名 `.xlsx` 附件；
- 只取“数据截至”日期最新的一期，历史批次不合并、不重复采集。

以 2026-07-13 一期为例（广州市）：省卫健委 42 条、省中医药局 7 条、
市卫健委 243 条，共 292 条，全部带机构地址。字段固定为序号、机构名称、
登记号、机构第二名称、机构地址、法人/负责人、行政区划、机构类别、
机构级别、经营性质、床位/牙椅、诊疗科目。

## 2. 数据模型

建议顶层记录继续使用公共地址记录格式，场景字段放 `attributes`：

```json
{
  "place_name": "机构第一名称",
  "original_address": "官方机构地址整格文本",
  "address_mode": "government_list",
  "source_nature": "government_information",
  "source_reference": "来源页面/附件 | 工作表 | 行号",
  "attributes": {
    "administrative_unit": "越秀区",
    "institution_category": "综合医院/医学检验实验室/中医（综合）医院…",
    "institution_level": "三级/二级/一级/未定级",
    "license_no": "登记号（来源提供时保留，用于去重）",
    "publication_date": "2026-07-29"
  }
}
```

关键规则：

- 主键优先使用“登记号”，而不是机构名称；同一机构多次出现在不同年度
  名单时按最新发布日期保留；来源没有登记号时退化为“机构名称 + 地址”
  去重。
- 机构级别只保留三级/二级/一级；来源写“三级甲等”“二级乙等”时规范为
  三级/二级。来源没有级别（常见于诊所、门诊部）不推断，留空或“未定级”。
- 机构类别保留官方原文（如综合医院、医学检验实验室、中医（综合）医院），
  与级别同表时进入主表；来源没有类别则留空，不阻塞提取。
- 经营性质、诊疗科目、床位数等不作为必需字段，也不进主表。
- `original_address` 保留官方“机构地址”整格文本；同一行含多个地址时
  仍一证一行，不做强制拆分、不额外检索。

## 3. 输出粒度（默认：一证一行）

默认：**一条发证记录一行**，地址列保留官方整格地址。

原因：

- 卫健委表格本身就是“一证一行”，地址已经写成可用的执业地址文本；
- 用户要求的是机构信息/地址表，不是逐建筑导航清单；
- 广东省人民医院这种“一行多地址”保留在同一行，仍可直接阅读和筛选。

如果后续确需“一个执业地点一行”用于导航，再在医疗机构 Skill 内做
地点拆分，不影响本方案主体。

## 4. 复用现有公共层

| 步骤 | 复用组件 |
| --- | --- |
| 栏目页发现 | `query_city_core/official/collectors`：`directory_links` |
| 附件下载 | `query_city_core/official/collectors`：`source_files` |
| HTML/Excel/PDF/图片读取 | `query_city_core/official/readers` |
| 检查/提取计划 | `query_city_core/official/extract` + 场景词表 |
| 地址规范化/地图兜底 | `python -m query_city_core.address.process` |
| Excel 样式 | `query_city_core.excel_style` |
| 并发与访问审计 | `access.py`、`host_gate.py`、`web/` |

医疗机构的地址层模式为 `government_list`：有效官方地址直接采用，
不再额外调用高德；地址为空或明显不可用的记录保留官方文本并进异常表，
不自动补查。核心层不新增医院/诊所语义。

## 5. 医疗机构特有场景逻辑（只放在 Skill 内）

1. **来源分层与覆盖**：
   - 记录省卫健委、省中医药局、市卫健委三份来源与去重后机构数；
   - 同一登记号在省、市批次同时出现时保留一份（按“市/省”和最新日期
     去重），主键仍优先用登记号。
2. **机构级别归一**：三级甲等/三级 → 三级，二级乙等/二级 → 二级，
   一级 → 一级；无级别留空或“未定级”。卫健委本期数据本身只有
   三级/二级/一级/无级别，不包含甲等/乙等，因此不为甲等乙等单开列；
   若未来其他来源出现“三级甲等”等原文，只在 JSON 的
   `level_raw` 中保留，不进主表。
3. **机构类别保留**：类型列用于区分医院、诊所、医学检验实验室、
   血液透析中心等；取值较多且来源同表，不归一化，直接保留官方原文。
4. **多地址同行防错**：官方地址整格保留，不做 POI 唯一性判断，也不因
   一行含多个区县而丢弃。

开始医疗场景前还需清理一处同类泄漏：`official/extract/rules.py`
生成的规则键仍是 `school_type_column`/`school_nature_column` 等学校
命名。建议先把规则键泛化为 `type_column`/`nature_column`（或由场景
词表映射），避免医疗机构再复制一套“institution_type”私有写法。

## 6. 工作表结构建议

行政单位工作簿：

- “机构信息”表：序号、行政单位、机构名称、机构类别、机构级别、地址、
  地址获取方式、地图匹配状态、信息来源。
- “异常机构”表：行政单位、机构名称、机构类别、机构级别、异常原因、
  地图匹配状态、信息来源。

城市总表 = 各行政单位“机构信息”之和。登记号、发布日期等溯源字段只保留
在 JSON 中间文件里，不进主表。

## 7. 验收标准

- 每个行政单位有明确来源或“该层级无公开名单”的结论；
- 省/市/区三类来源各自能追溯到原始页面与附件；
- 同一登记号不重复，跨来源更新按最新日期保留；
- 每条输出记录都能对应原表格行，地址保持官方整格文本；
- 原有最终地址记录在重跑后不回退；
- Excel 行数与区级之和一致，异常机构原因完整。
