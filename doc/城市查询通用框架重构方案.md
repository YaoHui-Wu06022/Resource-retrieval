# 城市查询通用框架重构方案

## 目标

让 `query-city-core` 成为真正通用的“城市查询”基础层，而不是围绕高校、
基础教育或医疗机构写死。任何新场景（医院、企业、政府机关等）通过
“补充场景词表 + Skill 薄层”接入，不修改公共地址流程与字段。

## 目录结构（目标态）

```text
query_city_core/
  address/              # 城市上下文、地图客户端、地址规范化/验证/处理
    city.py             # 由根目录迁入
    amap_client.py      # 由根目录迁入
    common.py
    normalize.py
    verify.py
    process.py
  official/             # 政府公开资料：收集、读取、检查、提取
    readers/
    collectors/
    extract/
      rules.py          # 通用 FieldTerms/规则推断，输出中性字段
      planner.py        # 通用 inspect_government_source
      executor.py       # 通用 extract_government_records
  web/                  # 官网页面与域名证据
    fetch_official_page.py
    probe_domains.py
    page_extractor.py   # 通用页面证据/地址候选基础能力
  access.py
  host_gate.py
  env_utils.py
  io_utils.py
  excel_style.py        # 通用地址结果工作簿列与生成器
```

Skill 薄层形态：

- 政府资料类（基础教育、医疗机构）：每个 Skill 保留
  `build_excel.py`、`build_<场景>_address.py`、
  `extract_<场景>_records.py`、`normalize_<场景>_records.py`；
  `inspect_government_source` 由 `official/extract` 通用实现，Skill
  只提供词表和覆盖要求。
- 官网检索类（高校、后续企业）：每个 Skill 保留
  `build_excel.py`、`build_<场景>_address.py` 和官网补充提取脚本；
  页面抓取、访问审计与域名证据来自 `web`。

## 字段设计（默认建议，待确认）

公共地址记录只使用中性字段：

```json
{
  "stage": "address_records",
  "city_context": {},
  "items": [
    {
      "place_name": "地点名称",
      "original_address": "来源地址",
      "address_mode": "government_list | web_search | map_search",
      "source": {
        "nature": "government_information | web_search | map_search",
        "reference": "来源定位",
        "date": "查询日期或来源日期"
      },
      "attributes": {}
    }
  ]
}
```

核心层不校验 `attributes` 内部的具体 key。场景字段（学校类型、机构
级别、主管部门、登记号等）只存在于 Skill 提取层与 Excel 领域列映射。

通用输出列（日期位置沿用“领域列之后、地址列之前”）：

```text
序号 | [领域列…] | 日期 | 地址 | 地址获取方式 | 地址匹配状态 | 信息来源
```

## 现状差异

- `city.py` 与 `amap_client.py` 仍在 `query_city_core` 根目录。
- `official/extract/rules.py` 已使用通用 `FieldTerms`，但输出仍含
  `school_type_column`、`school_nature_column` 等场景字段。
- 三个 Skill 的 `build_excel.py` 各自实现重复的地址列生成、异常行与
  校验逻辑。
- 政府资料来源还没有统一使用“government_source → inspect →
  extraction plan → extract”的公共链路。

## 实施顺序（默认建议）

1. 迁入 `city.py`、`amap_client.py` 到 `address/`，保留根目录兼容
   re-export，测试全部通过。
2. 泛化 `official/extract`：规则输出改为中性字段，新增通用
   `inspect_government_source` 与 `extract_government_records`；
   基础教育先迁移，医疗机构随后迁移。
3. 统一 Excel 生成器与日期列；三个 Skill 的 `build_excel.py` 改为薄
   包装。
4. 高校 Skill 保持官网检索私有逻辑，仅改 import 到 `web/` 新路径。

## 待确认

- 日期列语义：公共列用“查询日期”，来源日期是否保留为可选领域列。
- `attributes` 是否接受为不透明业务对象。
- 重构落地顺序是否按“公共层 + 政府来源 Skill 优先，高校随后”。
- `official` 与 `web` 的归属是否按本方案理解。
