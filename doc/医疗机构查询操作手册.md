# 医疗机构查询操作手册

本文依据 [query-city-medical-institutions Skill](../.agents/skills/query-city-medical-institutions/SKILL.md) 整理，按实际执行顺序说明操作、判断规则和完成条件，供了解流程、执行检查和验收结果时使用。

## 一、任务目标与范围

输入一个中国城市，检索政府公开的持证、登记或备案医疗机构资料，整理机构名称、类型、级别和执业地址，生成各直接下级行政单位工作簿及城市汇总 Excel。

- **行政范围**：使用城市组件返回的直接下级行政单位，不自行增加、合并或向更低一级拆分。下文的“各单位”均指这些行政单位，不限定为市辖区。
- **机构范围**：医院、诊所、门诊部、社区卫生服务中心和站、村卫生室、医学检验实验室等持证或备案医疗机构。
- **资料来源**：政府卫生部门、政府门户发布的官方注册查询平台、全量名单及相关公示。地图、百科、媒体和第三方机构库不能作为名录来源。
- **地址口径**：采用实际执业地址。登记所在区和实际执业所在区可能不同，同一登记记录也可能对应多个执业地点。
- **地址处理**：默认采用政府官方地址，最终工作簿不依赖地图结果；只有空地址或异常地址需要地图补全时，才准备相应密钥。

各单位工作簿包含“机构信息”和“异常机构”。城市总表包含“机构信息”汇总及各单位明细工作表，不含异常机构表。多执业地点拆分和跨来源去重后，最终地址行数可能不同于原始登记记录数。

## 二、流程总览

确认运行条件 → 确认城市和行政单位 → 按市级优先检索官方来源 → 保存名单或采集查询平台分页 → 复核提取计划 → 提取机构并拆分执业地点 → 串行处理地址 → 全市去重并按物理地址归属生成工作簿 → 运行交付质量检查。

按行政单位顺序，逐单位完成第 3～6 步，一次只处理当前单位的来源目录。全部单位完成后，再串行处理地址，最后统一生成工作簿并验收。

Agent 负责确认来源、检查机构类别覆盖及复核提取计划；固定脚本负责解析字段、拆分地址、去重、排序和生成工作簿。来源清单及原始资料须经 Agent 确认后纳入。“批准提取规则”属于 Agent 的资料复核操作，不要求用户逐条批准。

## 三、分步操作

### 第 1 步：确认运行条件，建立本次任务目录

**操作：**

1. 确认用户要查询的城市。
2. 检查运行环境；尚未确认时先询问用户，确认后在本次任务执行过程中保持一致。
3. 检查 Excel 处理依赖和公共处理组件是否可用。
4. 如果官方在线查询页需要浏览器采集，检查对应浏览器及采集依赖。
5. 只有需要对空地址或异常地址进行地图补全时，才检查高德地图密钥是否已通过环境变量或项目配置文件提供。
6. 新建本次任务目录，按标准城市名、日期和时分秒组织，不覆盖历史结果。

目录约定：`output/<标准城市名>/<YYYY-MM-DD>/Medical_Institutions/<HHMMSS>/`。后文的行政单位目录均建立在此目录下。

**进入下一步的条件：** 用户已确认运行环境，本次实际需要的依赖、浏览器和公共组件可用。缺少必要条件时停止并说明，不自行安装，也不另写临时脚本替代固定流程。

### 第 2 步：确认标准城市名和行政单位清单

**操作：**

1. 使用城市组件取得标准城市名及直接下级行政单位清单。
2. 保存城市信息，按清单中的名称建立同名目录，不增删、合并或改名。
3. 记录行政单位总数，作为后续来源和结果覆盖的核对基准。
4. 按清单顺序逐单位执行来源检索、保存、计划复核和记录提取。

**本步产物：** 城市信息文件和完整的行政单位目录。

**进入下一步的条件：** 目录与行政单位清单一一对应，查询范围明确。某单位资料难以取得时仍需保留该单位的状态，不能从任务范围中删除。

### 第 3 步：检索官方来源，核对机构类别覆盖

**操作：**

1. 先查市级统一注册查询平台或市级发证全量名单，再查当前单位的全量名单。
2. 使用区级名单补充和校正市级结果，再检查省级发证名单，补充由省级部门发证的机构。
3. 个案备案、变更或审批公示只能作为具体机构的补充证据，不能当作全量名单。
4. 打开正文或附件，确认实际包含机构记录。统一搜索平台只用于定位页面，搜索结果摘要不能代替原始名录。
5. 分别检查医院、诊所、门诊部、社区卫生服务中心和站、村卫生室、医学检验实验室等类别，不能只找到医院就结束检索。
6. 对每类记录采用的官方来源，或在完成检索后给出有依据的“无公开名单”结论。

**来源采用顺序：**

| 顺序 | 来源 | 用途与要求 |
| --- | --- | --- |
| 1 | 市级统一注册查询平台、市级发证全量名单 | 优先建立覆盖基准；须能按行政单位筛选、枚举，或记录本身带有所在行政单位。 |
| 2 | 当前行政单位的全量名单 | 补充、校正市级资料。 |
| 3 | 省级发证名单 | 补充省级发证机构，保留适用范围。 |
| 4 | 个案备案或审批公示 | 补充具体证据，不替代全量来源。 |

**查询平台是否可以采用：**

- 由政府卫生部门运营。
- 可以按行政区过滤并分页，或返回带行政区字段的整市记录。
- 结果包含官方执业地址字段。
- 有“数据截至”日期或更新说明。

平台如果说明“区发证机构以各区卫健局为准”等适用口径，应保留该说明，并继续用区级来源补充；不能仅因存在这类说明就否定平台的证据资格。

**缺口处理：** 访问失败不等于没有官方来源，单次“没搜到”也不能作为结论。在线查询页不能直接下载时，应使用浏览器取得证据。确实没有可用全量名单时，记录检索结论和对应类别，不凭空补记录。

为方便最终质量核对，类别缺口统一对应五个大类：医院、基层医疗卫生机构、门诊部与诊所、医学检验机构、其他。这里的大类用于覆盖统计，工作簿中的机构类型仍保留官方原文。

### 第 4 步：保存名单，完整采集平台分页

**网页及附件来源的操作：**

1. 对栏目页先筛选候选链接，由 Agent 复核后采用。
2. 使用固定下载或详情页采集流程，保存实际包含名录的附件、正文和相关详情页。
3. 将原始文件存放到当前行政单位的 `sources/` 目录。
4. 登记发布或发证部门、来源网址、覆盖类别、官方数据截至日期和本地文件位置。

**官方查询平台的操作：**

1. 先将确认的平台登记为“待采集”，明确当前单位的筛选范围。
2. 通过既有平台采集流程逐页获取数据，不只保存首页或当前可见的一页。
3. 保存每页原始响应，并生成可供提取的汇总记录，保留页码和行位置以便追溯。
4. 检查平台总数、实际采集记录数和页数，确认分页采集完整；采集中总数变化或分页缺失应查明原因。
5. 成功后将来源更新为“已就绪”，登记本地汇总文件和原始页清单；失败则记录“采集缺失”及具体原因。

**来源状态的含义：**

| 状态 | 含义与后续处理 |
| --- | --- |
| 待采集 | 已确认来源，但尚未完成保存或平台采集。 |
| 已就绪 | 已有可用本地文件，可以进入检查和提取。 |
| 采集缺失 | 来源获取失败或资料缺失，需要排查，不能等同于无官方来源。 |
| 无官方来源 | 完成核查后，确认对应类别没有可用全量来源；必须注明类别和原因。 |

**本步产物：** 当前单位的政府来源清单、原始资料，以及平台分页证据和汇总文件。

**进入下一步的条件：** 所有拟提取来源均已就绪且有本地文件。固定提取流程只读取已就绪来源；待采集或采集失败的来源不能伪装成已完成。无全量来源的单位须保留缺口，后续不能通过最终质量检查。

### 第 5 步：检查资料并复核提取计划

**操作：**

1. 针对当前单位的来源清单，运行资料检查流程，生成提取计划。
2. 对照原始资料，确认名录所在的工作表、网页表格或平台记录列表。
3. 核对机构名称、机构类型、机构级别、执业地址、登记号及所在行政区等字段的位置。
4. 区分“登记区”“所在区”和实际地址中的行政区，不能把登记归属当成全部执业地点的物理归属。
5. 检查表头与内容是否对应，排除重复表头和说明文字，防止读取错列。
6. 平台内部记录编号不能直接当作执业登记号使用，以免与其他来源的登记号混淆，影响去重。
7. 由 Agent 对确认正确的规则标记批准，并将对应来源标记为可提取。

**进入下一步的条件：** 提取规则与官方资料一致，字段定位和行政归属含义已复核。不能仅凭自动生成的计划看起来完整就直接通过，也不手工抄写最终记录绕过固定提取流程。

### 第 6 步：提取机构记录，拆分多个执业地点

**操作：**

1. 根据已复核计划提取机构记录，保留官方名称、类型、级别及来源。
2. 官方未给出的类型或级别保留为空，不根据机构名称、规模或常识推断。
3. 对一条登记记录中列出的多个执业地点进行拆分，使不同物理地址可以分别处理。
4. 明确属于外市的地址段予以排除；同一城市内跨行政区的执业地址段保留，不能仅因它不属于当前目录就剔除。
5. 区分两层范围检查：来源记录仍按其行政区字段执行既有筛选；合法入选记录拆出的跨区执业地点，应留到最终按物理地址归属整理。
6. 使用固定规则合并同一单位内跨来源的重复记录，保留登记信息、来源页或文件及行位置。
7. 没有地址的机构记录仍予保留，供后续处理和异常表使用。
8. 检查结果确实进入待处理地址阶段，提取错误数必须为 0。

**本步产物：** 当前单位的机构原始地址记录。

例如：某机构登记在甲区，官方同一条记录列出了甲区和乙区两个执业地址。两处均属目标城市时，应分别保留，最终再将乙区执业点归入乙区工作簿。

**进入下一步的条件：** 提取无错误，多地址拆分有原文依据，外市段已排除，来源可追溯。按顺序完成其余单位的第 3～6 步后，再统一处理地址。

### 第 7 步：串行规范化地址，核对官方原文

**操作：**

1. 依次处理各单位地址，同一时间只运行一个地址处理进程。
2. 清洗和规范化地址表达，检查城市及行政单位归属。
3. 完整有效的官方地址直接采用，不要求每条都查询地图。
4. 对规范化冲突查看官方原文，区分真实外市地址、登记区与执业区不同，以及表达方式引起的处理冲突。
5. 规范化结果存在冲突，但官方地址仍可用时，后续工作簿阶段按规则保留官方地址，不能只因地图或规范化结果不理想就丢掉官方执业地点。
6. 只有空地址或异常地址需要地图补全时，才按既有流程处理；地图结果不能成为生成最终工作簿的强制依赖。

**地址取舍：**

| 情况 | 处理原则 |
| --- | --- |
| 官方地址完整有效 | 直接采用官方地址。 |
| 最终处理地址为空，但仍有可用官方原文 | 工作簿阶段按规则使用官方地址，并按实际物理地址归属整理。 |
| 明确属于外市的地址段 | 不进入本市有效结果。 |
| 最终地址和可用官方原文均为空 | 保留记录及原因，进入来源单位的异常机构表。 |
| 记录已有明确异常原因 | 交由异常机构规则处理，不强行放入有效结果。 |

**进入下一步的条件：** 各单位均有合法的地址处理结果，冲突及异常已检查，原始官方证据保留。最终处理地址为空不必然等于应当丢弃，还要检查是否有可用官方原文。

### 第 8 步：全市去重，按物理地址归属生成工作簿

**操作：**

1. 汇集所有行政单位的地址处理结果，先做城市级跨目录去重。
2. 优先按登记号和地址识别重复；其次依据机构名称、行政单位和地址识别重复，避免同一机构在市级、区级、省级来源中反复计数。
3. 去重后按最终物理地址归属各单位；没有最终处理地址时，按可用官方原文地址判断。
4. 将跨区执业地点放入对应物理行政单位的工作簿，不固定保留在登记区。
5. 无地址的异常记录保留在来源单位目录中的“异常机构”，不另外建立独立异常清单文件。
6. 由脚本完成排序、列序和工作簿格式，不手工调整成表数据。

**工作簿内容：**

| 文件或工作表 | 收录内容 |
| --- | --- |
| 各单位“机构信息” | 归属于该物理行政单位、可作为有效结果的机构地址。 |
| 各单位“异常机构” | 最终地址为空且无可用官方原文，或带有明确异常原因的记录；异常原因不能为空。 |
| 城市总表“机构信息” | 全市去重并完成物理归属后的有效地址汇总。 |
| 城市总表各行政单位明细页 | 对应单位的有效地址记录；城市总表不含异常机构表。 |

“机构信息”共 10 列，包含行政单位、机构名称、类型、级别、查询日期、地址、地址获取方式、地图匹配状态及信息来源等内容；“异常机构”共 8 列，保留身份信息、异常原因和来源。

机构类型和级别以官方原文为准，缺失不补造。级别为“未定级”“无定级”“无级别”时，工作簿中该列显示为空，原始处理记录仍保留官方文字。

**本步产物：** 各单位的 `医疗机构信息_<行政单位>.xlsx`，以及运行目录中的 `医疗机构信息_<标准城市名>_<YYYY-MM-DD>.xlsx`。

**进入下一步的条件：** 工作簿可以正常打开，各单位双表齐全，城市汇总有效行数等于各单位有效行数之和，不含明确外市地址段。

### 第 9 步：执行交付质量检查，核对数量与类别

生成工作簿后，必须运行既有医疗质量检查流程。质量报告通过才算完成，不能仅以“文件已经生成”作为交付依据。

**操作：**

1. 检查每个单位是否有已就绪的全量来源。只有个案公示，或来源仍待采集、缺失，不能认定已完成全量检索。
2. 有已就绪官方查询平台的单位，比较其平台记录总数和交付主表行数。
3. 比较平台和交付结果的机构大类数量，检查是否整类遗漏。
4. 查看质量报告中的各单位数量、比例、类别统计及未通过原因。
5. 未通过时回到对应的来源、分页采集、提取或地址归属步骤修正，重新生成工作簿并再次检查。

**默认通过要求：**

| 检查项 | 要求 |
| --- | --- |
| 全量来源 | 每个单位至少有一个已就绪的全量来源；没有则该单位未完成。 |
| 平台数量下限 | 有可用平台的单位，交付主表行数不得低于平台当区总数的 90%。 |
| 大类覆盖 | 平台某大类达到默认 10 条，而交付结果为 0 时，必须有对应类别“无官方来源”的依据说明，否则不通过。 |
| 最终报告 | 质量报告明确显示通过；未通过不得按完整成果交付。 |

90% 是发现大规模漏采的检查下限，不是允许主动少采的目标。某类缺口有依据说明，也不能替代每个单位必须具备全量来源的要求。

**完成检查清单：**

- [ ] 运行环境已经用户确认，本次执行保持一致。
- [ ] 行政单位目录齐全，每个单位有来源清单和合法的原始地址、处理结果文件。
- [ ] 采用的来源经过确认，已就绪来源均有本地文件。
- [ ] 平台分页完整，官方数据截至日期和适用口径已保留。
- [ ] 机构类别覆盖已核对，缺口有对应类别和依据说明。
- [ ] 提取规则已复核，错误数为 0，记录可定位到来源文件或页面及行位置。
- [ ] 多执业地点已拆分，跨区地点未因登记区不同而误删，明确外市段已排除。
- [ ] 城市级去重完成，再按物理地址归属分配各单位结果。
- [ ] 各单位工作簿双表齐全，异常原因非空；城市总表不含异常机构表。
- [ ] 城市有效地址行数等于各单位之和，工作簿可正常打开。
- [ ] 交付质量报告通过，数量和大类覆盖不存在未解决的阻断问题。

完成后向用户提供：标准城市名、行政单位总数及来源状态计数、机构类别覆盖情况、平台数据截至日期与口径说明、最终地址行数，以及最终文件绝对路径。逐来源检索过程保留在任务目录中。

## 四、遇到问题时回到哪一步

| 问题 | 返回位置与处理方式 |
| --- | --- |
| 运行环境未确认或必要依赖缺失 | 第 1 步：先确认环境，说明缺项，不预设具体环境。 |
| 只有医院名单，其他机构类型缺失 | 第 3 步：继续检查全量平台和各层级来源，逐类记录覆盖。 |
| 只有个案审批、变更或备案公示 | 第 3 步：继续寻找全量来源，个案公示不能代替全量。 |
| 查询平台打不开或不能直接下载 | 第 4 步：检查访问方式，必要时通过浏览器采证，不直接标记无来源。 |
| 平台总数与采集数量不一致 | 第 4 步：核对筛选条件、分页和总数变化，补齐原始证据后重新提取。 |
| 登记区与执业地址所在区不同 | 第 5～8 步：核对字段含义，保留合法跨区地点，再按物理地址分配结果。 |
| 提取错误或字段错位 | 第 5～6 步：修正提取计划，重新提取至错误数为 0。 |
| 规范化冲突但官方地址清楚 | 第 7 步：复核官方原文，按规则保留可用官方地址。 |
| 机构在多个单位或多个来源中重复 | 第 8 步：检查登记号、名称及地址，执行全市去重后重新生成。 |
| 质量检查未通过 | 第 9 步：按报告定位数量、类别或全量来源缺口，修正后重新检查。 |
