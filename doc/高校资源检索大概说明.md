## 目标

根据用户输入的城市，从当前工作目录中的{全国普通高等学校名单.xlsx}筛选该城市的全部普通高校。

根据名单中的原始办学层次，对本科院校进一步判定985、211标签。限时检索学校官方网站中的校区地址，并使用地图数据辅助验证官网地址，最终生成Excel。

官网是学校地址的首要事实来源。正常情况下，地图数据仅用于验证官网地址，不得覆盖、补全或替换官网已明确提供的地址。

仅当官网检索预算已耗尽且未获得有效地址时，允许使用地图数据作为受限兜底来源。地图兜底必须明确标记，不得伪装为官网地址。

## 输入

接受一个中国城市名称，例如：

- 广州市
- 广州

如果用户没有提供城市，先询问城市名称，不要询问已经明确提供的信息。

## 输入文件

从当前工作目录读取以下三个文件：

1. `全国普通高等学校名单.xlsx`
2. `985_universities.xlsx`
3. `211_universities.xlsx`

如果缺少必要文件，停止处理并明确列出缺失文件。

## 输出文件

输出文件名：

`高校建筑查询_<标准城市名>_<YYYY-MM-DD>.xlsx`

例如：

`高校建筑查询_广州市_2026-08-25.xlsx`

工作簿必须包含两个工作表：

1. `高校信息`
2. `查询日志`

## 主表字段

`高校信息`工作表按以下顺序输出：

| 字段       | 内容                                               |
| ---------- | -------------------------------------------------- |
| 序号       | 教育部名单原始序号                                 |
| 学校名称   | 教育部名单                                         |
| 学校标识码 | 教育部名单，按文本保存                             |
| 主管部门   | 教育部名单                                         |
| 所在地     | 教育部名单                                         |
| 校区       | 多校区时填写；只有一个地址时留空                   |
| 官网地址   | 学校官方页面提取的地址；未获取则留空               |
| 地图地址   | 地图服务返回的标准地址；无结果留空                 |
| 最终地址   | 最终用于输出和后续分析的地址                       |
| 办学层次   | 本科/专科                                          |
| 院校标签   | 985/211，普通本科或专科留空                        |
| 办学性质   | 公办、民办、中外合作、境外机构；异常情况可为待核验 |
| 来源链接   | 实际支持官网地址的官方页面；地图兜底时留空         |
| 时效       | 地址查询日期，格式为YYYY-MM-DD                     |

## 第一步：标准化城市名称

按照以下顺序处理：

1. 先与教育部名单中“所在地”的唯一值进行精确匹配。
2. 如果没有精确匹配且输入不以“市”结尾，尝试匹配“输入值+市”。
3. 只有一个匹配结果时使用该结果作为标准城市名。
4. 如果出现多个可能结果，必须询问用户。
5. 禁止使用无约束的包含匹配。

例如：

- `广州`可以标准化为`广州市`。
- 直辖市： 北京、上海、天津、重庆直接映射为对应市级名称

## 第二步：读取教育部名单

不要假定表头永远位于固定行。

在工作表前若干行中查找同时包含下列字段的表头行：

- 序号
- 学校名称
- 学校标识码
- 主管部门
- 所在地
- 办学层次
- 备注

当前文件通常在第3行出现表头，但必须以字段检测结果为准。

跳过以下内容：

- 标题行
- 空行
- “北京市（92所）”之类的地区分组行
- 没有有效学校名称或学校标识码的行

学校标识码必须作为文本处理，不得转换为科学计数法。

## 第三步：筛选学校

筛选条件：

- `所在地 == 标准城市名`

## 第四步：判定院校标签

只名单中`办学层次 == 本科`的院校进行985、211匹配

分别读取：

- `985_universities.xlsx` 
- `211_universities.xlsx`

在工作簿中查找学校名称字段，必须采用学校名称完全匹配。

判定顺序： 

1. 办学层次不是本科：   
   - `院校标签`留空
   - 不参与985、211匹配
2. 本科院校命中985名单：
   - `院校标签 = 985`
3. 未命中985但命中211名单：
   - `院校标签 = 211`
4. 均未命中：   
   - `院校标签`留空

985判定必须先于211判定，985院校即使也出现在211名单中，只填写`985`

## 第五步：判定办学性质

读取名单的“备注”字段，按照以下优先级判断，顺序不能改变：

1. 备注包含“中外合作办学”或“内地与港澳合作办学”：
   - `办学性质 = 中外合作`
2. 备注包含“境外高等教育机构”：
   - `办学性质 = 境外机构`
3. 备注包含“民办”：
   - `办学性质 = 民办`
4. 备注为空、空白或缺失：
   - `办学性质 = 公办`
5. 备注非空但没有命中以上规则：
   - `办学性质 = 待核验`
   - 同时写入查询日志
   - 不得自动归为公办

## 第六步：查找学校官网

对每所学校设置严格的检索预算：

- 每所学校最多进行1次Web Search，仅允许一个查询请求
- 最多读取3个官方页面，不得拓展搜索。

推荐搜索词：`"<学校名称>" 官网 地址`

只允许采用以下来源：

1. 学校官方网站首页
2. 学校官网中的“联系我们”
3. 学校官网中的“学校概况”
4. 学校官网中的“校区介绍”
5. 学校官方二级单位页面

搜索引擎仅用于发现官方页面，禁止将搜索结果摘要或其它第三方页面直接作为地址来源；

### 官方域名判断

优先确认

- `edu.cn`域名
- 学校公开使用的其它官方域名

若学校 `edu.cn` 官网出现502等无法访问情况，可尝试搜索页面标题与学校名称匹配的 `.cn` 域名

禁止将以下来源作为官网地址来源：

- 百度百科
- 高德
- 百度地图
- 新闻媒体
- 聚合网站
- 招聘网站

## 第七步：页面抓取

官方页面访问必须通过页面抓取工具执行，优先使用真实浏览器渲染抓取：

- 工具：Playwright
- 浏览器：Headless Chromium

首次使用时安装

```bash
python -m pip install playwright
python -m playwright install chromium
```

抓取参数：

```python
page.goto(
    url,
    timeout=40000,
    wait_until="domcontentloaded"
)
```

浏览器访问要求：

- 设置真实浏览器 User-Agent。
- 自动跟随 HTTP 跳转。
- 保留最终访问 URL。
- 最终访问 URL 必须仍属于学校官方域名或官方二级单位域名。

必须检查首页页脚中的地址信息

以**首页页脚 + 学校概况/校区介绍页中能够确认的校区信息并集**为准

### 页面访问计数

页面访问数按照实际主动访问的不同页面 URL 计数：

- 主动访问一个新的页面 URL → 计 1 次；
- HTTP 自动跳转不额外计数，只记录最终 URL；
- 同一 URL 因超时、网络错误等进行技术重试，不重复计数；
- 主动尝试不同的 HTTP/HTTPS URL，视为不同页面访问；
- Tab 切换、锚点跳转不增加页面访问数；
- `已访问链接`优先记录最终访问 URL。

`访问页面数`必须与实际访问行为一致，每所学校不得超过3次。

### HTML与DOM处理限制

不得将完整页面 HTML 直接输出到模型上下文中，避免受到工具输出长度或上下文长度限制而被截断

页面抓取后应优先在本地完成 DOM 筛选，只向后续步骤返回任务相关信息，包括：

- 页面标题
- 最终 URL
- 包含“地址”“校区”等关键词的正文片段
- 页脚文本
- 校区名称
- 校区地址
- 与“联系我们”“学校概况”“校区介绍”相关的链接

对于需要检查隐藏 Tab 内容的页面： 

1. 可以使用 `page.content()` 获取完整渲染后 DOM； 
2. 完整 HTML 仅用于本地解析，不得整体输出到模型；
3. 使用 BeautifulSoup、lxml 或 DOM selector 在本地筛选目标节点；
4. 只将筛选后的相关文本返回模型

Tab 页面优先解析 DOM 中的全部校区信息；未预加载的内容再通过 Playwright 点击 Tab 获取。

若需要调试完整 HTML，应将 HTML 保存为本地文件，而不是打印到标准输出。

## 第八步：官网访问顺序

按照以下顺序访问：

1. 官网首页。
2. 根据页面链接和搜索结果选择一个最相关页面：
   - 校区介绍
   - 联系我们
   - 学校概况
3. 如果第二个页面仍不足，再从上述候选中选择一个尚未访问的页面。

停止条件：

- 已获得官网明确列出的全部输入城市校区地址时，立即停止。
- 已访问3个官方页面时，无论成功与否都停止。
- 如果首页只出现一个联系地址，但同时明确提到多个校区，不得将该联系地址视为全部校区地址；可以继续访问校区介绍页面。

不得遍历新闻、招生简章、院系列表、网站地图或大量二级页面。

## 第九步：提取与确定地址

### 官网地址

提取官网地址时：

- 只保留实际地址；
- 删除电话、传真、邮箱和邮政编码等非地址内容；
- 保留门牌号、道路、区县和城市等地址组成部分；
- 不擅自补充官网没有提供的门牌号；
- `来源链接`填写实际支持该官网地址的官方页面，不得统一填写官网首页。

官网地址需要规范化为：

```
XX省 + XX市 + XXX
```

直辖市规范为：

```
XX市 + XX区 + XXX
```

地址格式化只允许调整行政区表达，不得新增官网没有提供的信息

### 地图辅助

正常情况下，只有获得官网地址后才进行地图验证。

服务优先级：

1. 高德 Web 服务 API；
2. Nominatim 兜底。

高德接口：

```
restapi.amap.com/v3/geocode/geo
```

使用高德前需要配置 Key；未配置时可降级使用 Nominatim。

每个官网校区地址最多进行1次地图查询。地图查询不计入Web Search次数和官方页面访问数，但必须单独记录。

高德请求必须统一进行限速：

- 速率 ≤ **3次/秒**
- 禁止多个执行单元或并行子代理分别独立并发调用高德

官网地址与地图地址必须分别保存。

地图不得修改、补充或覆盖已经获得的官网地址，即使地图返回更具体的道路或门牌号，也只能写入`地图地址`字段

### 地图验证判定

地图验证状态按照以下规则判定：

- 地图返回的 `formatted_address` 与官网地址在省、市、区县、道路、门牌号层面吻合 → `一致`
- 地图只解析到区级或POI级，或者地址细节不完整但能够确认属于同一地点 → `部分一致`
- 地图结果位于非输入城市，或与官网地址存在明显行政区、道路等冲突 → `冲突`
- 地图服务正常，但没有返回有效结果 → `未找到`
- 地图服务不可用、Key无效或网络失败 → `未验证`

发生冲突时以官网地址为准，不得使用地图地址覆盖官网地址。

### 地址兜底

仅当官网检索预算已经耗尽且未获得有效官网地址时，才允许使用地图进行受限兜底

必须同时满足：

1. 官网检索预算已经耗尽，且未获得有效官网地址；
2. 使用教育部名单中的完整学校名称进行地图查询；
3. 地图结果中的机构名称与学校名称完全一致或能够明确确认属于该学校；
4. 地图结果明确位于标准城市；
5. 返回结果具有可用的标准地址；
6. 不存在多个无法区分的候选结果。

### 最终地址判定

`官网地址`和`地图地址`必须分别保存，不互相覆盖。

`最终地址`按照以下优先级确定：

1. 已获得有效官网地址：
   - `最终地址 = 官网地址`
2. 未获得有效官网地址，但满足地图兜底条件：
   - `最终地址 = 地图地址`
3. 官网和地图均未获得可靠地址：
   - `最终地址`留空

只要存在有效官网地址，最终地址必须优先使用官网地址。

## 第十步：多校区处理

### 只有一个地址

输出一行：

- `校区`留空
- 根据地址来源填写`官网地址`或`地图地址`
- `最终地址`按照最终地址判定规则填写

只提取到一个地址时也可以保持`校区`为空，除非必须依靠校区名称区分地址

### 多个明确校区

如果官网明确给出多个“校区名称+地址”，每个校区输出一行。

每一行重复填写该学校的教育部字段、办学层次、院校标签和办学性质。

每个校区的官网地址、地图地址、最终地址分别填写。

### 校区保留

只输出能够确认位于输入城市的校区。

城市判断顺序：

1. 地址明确包含标准城市名。
2. 页面上下文明确说明该地址位于标准城市。
3. 地址只写区县，但该区县可以可靠确认属于输入城市。

如果无法确认行政归属：

- 不输出该校区地址。
- 在查询日志中记录`校区城市归属无法确认`。
- 不得猜测。

### 多地址但没有校区名称

如果官方页面给出多个地址，但没有给出对应校区名称：

- 每个地址分别输出。
- `校区`填写`未注明校区`。
- 不得根据地名自行编造校区名称。

### 没有找到输入城市内地址

如果官网检索和地图兜底均未获得输入城市内有效地址，仍保留该学校的一行基本信息：

- `校区`留空；
- `官网地址`留空；
- `地图地址`根据实际查询结果填写或留空；
- `最终地址`留空；
- `来源链接`填写已确认的官网首页；如果官网也未确认则留空；
- 在查询日志中记录失败原因。

这样保证主表不会因为官网查询失败而漏掉教育部名单中的学校。

### 去重

主表按照下列组合去重：

`学校标识码 + 校区 + 标准化地址`

不得通过模糊地址相似度合并不同校区。

## 查询日志

`查询日志`工作表至少包含：

| 字段           | 内容                                           |
| -------------- | ---------------------------------------------- |
| 学校名称       | 教育部学校名称                                 |
| 查询状态       | 成功、部分成功、失败、待核验                   |
| Web Search次数 | 0或1                                           |
| 访问页面数     | 0、1、2、3                                     |
| 已访问链接     | 用换行分隔                                     |
| 地图验证状态   | 一致、部分一致、未找到、未验证、兜底           |
| 失败或异常原因 | 地址缺失、官网未确认、城市归属不明、地图冲突等 |
| 查询时间       | YYYY-MM-DD                                     |

查询日志以学校为单位，不以地址记录为单位。

`失败或异常原因`只记录实际失败、缺失、冲突或待核验事项。

- 查询状态为`成功`且不存在异常时，该字段必须留空；
- `部分成功`填写未获取到的校区或其它缺失原因；
- `失败`填写具体失败原因；
- `待核验`填写具体冲突或异常原因。

正常的地址获取过程、成功依据、校区确认说明不得写入`失败或异常原因`。

## Excel格式

生成工作簿时：

- 学校标识码设置为文本格式。
- 时效和查询时间使用真正的日期值，显示格式为`yyyy-mm-dd`。
- 表头加粗并设置清晰底色。
- 冻结首行。
- 启用自动筛选。官网地址、
- 地图地址、最终地址、来源链接和失败原因允许自动换行；
- 来源链接保留完整URL，原则上不启用自动换行，并设置足够列宽，避免URL在字符中间产生视觉断行；
- 设置合理列宽，避免表头和关键内容被截断。
- 不创建无内容的默认工作表。
- 来源链接保留完整URL。

## 完成前验证

输出前必须执行以下检查：

1. 教育部名单中所有`所在地 == 标准城市名`的学校都必须至少出现在主表一次。
2. 主表中学校标识码去重数量必须等于教育部名单筛选学校数量。
3. 多校区拆行后，主表总行数可以大于学校数量。
4. `办学层次`必须保留教育部原始值，只能据源表填写。
5. 只有办学层次为本科的院校才参与985、211匹配。
6. 非空`来源链接`必须是学校官方域名或官方二级单位域名；地图兜底记录允许来源链接为空。
7. 每所学校Web Search次数不得超过1。
8. 每所学校访问页面数不得超过3。
9. 不得包含重复的`学校标识码+校区+地址`组合。
10. 有有效官网地址时，`最终地址`必须等于`官网地址`。
11. 使用地图兜底时，`官网地址`必须为空，`最终地址`必须等于`地图地址`。
12. 检查主表和查询日志是否存在明显空表、乱码、科学计数法或截断问题。
13. 如果验证失败，修复后重新生成，不得直接交付错误文件。

## 失败处理原则

遇到无法确认的信息时：

- 对无法确认的字段留空；
- 除本Skill明确允许的地图兜底外，不使用第三方网站补齐地址；
- 不根据模型记忆填写。
- 在查询日志中说明具体原因。
- 继续处理其他学校，不因单所学校失败而终止整个任务。

只有输入文件缺失、工作簿无法读取或输出文件无法创建时，才终止整个任务。
