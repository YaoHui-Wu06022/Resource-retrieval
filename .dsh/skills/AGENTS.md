# Skills Python 命名规范

## 适用范围

- 本文件继承 `E:\DSH\AGENTS.md` 的通用编码规范。
- 下述规范适用于 `.dsh/skills/` 下所有 Skill 的 Python 脚本和测试。
- 新增或修改代码时遵守本规范，不得借此批量重命名当前任务未涉及的代码。

## Python 函数命名

- 函数、参数和变量统一使用英文 `snake_case`，常量使用 `UPPER_SNAKE_CASE`。
- 函数名使用“动词 + 领域对象”，名称必须说明动作和处理对象。
- 脚本入口统一命名为 `main`。
- 每个函数定义后必须写一行简短的中文 docstring，准确说明函数功能。
- 顶层函数默认不添加前导 `_`，不得仅因函数当前只在本文件调用就批量添加 `_`。
- 集合变量使用复数名称，单条记录使用单数名称。
- `is_` 表示对象当前是否处于某种状态，例如 `is_resource_available`。
- `has_` 表示对象是否包含或存在某项内容，例如 `has_required_fields`。
- `can_` 表示当前是否具备执行某个动作的条件或能力，例如 `can_retry_request`。
- `should_` 表示根据业务规则是否应执行某个动作，例如 `should_skip_record`。
- 路径、目录、网址和数量分别使用 `_path`、`_dir`、`_url` 和 `_count` 后缀。
- 允许使用 `html`、`css`、`pdf`、`json`、`api`、`url`、`id` 等通用技术缩写。

## 动词约定

- `read_`：从本地资源读取原始内容或记录。
- `load_`：读取并组装为程序直接使用的完整对象。
- `open_`：打开资源并返回可继续操作的对象或句柄。
- `find_`：查找并返回符合条件的对象或位置。
- `fetch_`：通过网络获取页面、文件或 API 数据。
- `parse_`：把文本、HTML 或响应转换为结构化数据。
- `inspect_`：检查文件或数据结构并返回描述信息。
- `extract_`：从已有结构中提取字段或记录。
- `normalize_`：清洗并统一表达形式。
- `classify_`：根据固定规则生成类别。
- `filter_`：筛选集合并返回子集。
- `validate_`：执行校验，失败时抛出异常。
- `verify_`：核对已经生成的结果。
- `is_`、`has_`、`can_`、`should_`：返回对应语义的布尔值。
- `collect_`：汇集多个同类输入。
- `build_`：在内存中构造记录、计划或工作簿。
- `convert_`：转换文件或数据格式。
- `format_`：生成用于展示或持久化的格式化值。
- `write_`：把结果持久化到文件。
- `resolve_`：根据配置或候选确定唯一结果。
- `split_`：按明确规则拆分字段或记录。
- `merge_`：合并同类记录或字段。
- `deduplicate_`：移除重复记录。
- 上述列表不是封闭集合；使用其他动词时必须准确说明函数行为。

## 禁止事项

- 不新增 `process_`、`handle_`、`do_` 等不能说明具体行为的函数名。
- 不使用 `_helper`、`_util`、`_func` 作为函数名后缀。
- 有明确业务含义时，不使用孤立的 `data`、`item`、`value`、`result`、`text` 作为变量名。
- 除已允许的通用技术缩写外，不使用含义不明确的缩写。
- 不通过变量名重复表达 Python 类型，例如 `school_list`、`result_dict`。
- 不把具体地区、机构、人员、项目或单一案例写入通用函数名。
