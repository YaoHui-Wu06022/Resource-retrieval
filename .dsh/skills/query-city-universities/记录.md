# 高校查询 Skill 已确认设计

## 当前范围

本文只记录已经确认的高校私有流程、最终输出规则及其与公共组件的边界。

## 总体链路

运行高校私有脚本和公共地址组件时，统一使用 Conda 环境`py3.10`；非交互命令使用`conda run --no-capture-output -n py3.10 python ...`，避免 Windows 下 Conda 捕获输出时破坏中文参数。

```text
用户输入城市
  → 公共城市名称标准化
  → 高校名单基础处理
  → LLM 搜索学校官网
  → 高校官网页面抓取和地点提取
  → 高校私有层组装 address_records
  → 公共地址处理
  → 高校输出层
```

## 公共城市名称标准化

- 城市名称由`.dsh/components/normalize_city.py`统一处理。
- 高校脚本不得再根据教育部名单自行推断标准城市名。
- 标准名称精确命中时直接采用；普通城市和直辖市简称只允许补充一个`市`后精确命中。
- 不进行包含匹配、模糊匹配或自治州简称推断。
- 城市标准化完成后，高校名单固定使用`所在地 == 标准城市名`筛选。

## 高校私有基础处理

以下数据属于高校 Skill 私有资产和逻辑：

- `assets/全国普通高等学校名单.xlsx`
- `assets/985_universities.xlsx`
- `assets/211_universities.xlsx`
- 读取教育部高校名单。
- 按标准城市名称筛选学校。
- 仅对本科高校判定 985、211 标签。
- 根据教育部备注判定办学性质。

办学性质规则保持为：

- 包含“中外合作办学”或“内地与港澳合作办学”：`中外合作`；
- 包含“境外高等教育机构”：`境外机构`；
- 包含“民办”：`民办`；
- 备注为空：`公办`；
- 其它备注：`待核验`并记录原因。

教育部原始备注只用于判定办学性质，不作为后续地址字段。高校基础信息中哪些字段进入最终 Excel，留到输出层讨论。

### 高校字段与变量命名

教育部源表读入后立即转换为统一英文键。`base_information.json`、`university_page_results`和公共层`attributes`沿用同一组键，不在中间阶段重复翻译字段名。

| 源表或派生字段 | JSON字段 / Python变量 | 类型 | 传递范围 |
| --- | --- | --- | --- |
| 序号 | `source_sequence` | 数字字符串 | 保留到高校公共属性；表示教育部源表原序号 |
| 学校名称 | `school_name` | 字符串 | 全链路保留 |
| 学校标识码 | `school_identifier` | 数字字符串 | 全链路保留；不得与招生代码混用 |
| 主管部门 | `supervising_authority` | 字符串 | 全链路原样保留 |
| 所在地 | `location_city` | 字符串 | 全链路保留，并用于城市精确筛选 |
| 办学层次 | `education_level` | 字符串 | 全链路保留源值 |
| 备注 | `source_remark` | 字符串 | 仅保留在高校私有基础记录，不进入公共层和最终 Excel |
| 院校标签 | `school_tag` | 字符串 | 高校私有层派生后保留到公共属性 |
| 办学性质 | `school_nature` | 字符串 | 高校私有层派生后保留到公共属性 |
| 校区 | `campus_name` | 字符串 | 页面聚合阶段生成并进入公共属性 |

集合和临时变量统一使用：

| 含义 | Python变量名 |
| --- | --- |
| 教育部源表的一行 | `source_row` |
| 规范高校记录 | `school_record` |
| 高校记录集合 | `schools` |
| 目标城市高校集合 | `city_schools` |
| 985学校名称集合 | `school_names_985` |
| 211学校名称集合 | `school_names_211` |
| 当前高校 | `school` |

不再使用`idx`、`name`、`code`、`dept`、`location`、`level`、`remark`、`tag`、`nature`和`authority`作为高校业务字段键。

`base_information.xlsx`的“序号”继续显示`source_sequence`。最终汇总 Excel 的“序号”由输出层使用`display_sequence`按城市结果从1开始重新编号；`display_sequence`只用于展示，不写回高校基础记录，也不作为 ID。

## 官网搜索和域名边界

- 学校官网由 Agent 使用自身 Web Search 查找，不替换为外部搜索组件。
- 原则上每所学校执行一次 Web Search，最多访问三个官网页面。
- `.edu.cn`官网无法访问时，可以采用页面标题与学校名称相符的`.cn`官网。
- LLM 负责判断域名是否确属学校官网；抓取脚本只负责技术性域名边界校验。
- 请求 URL 和跳转后的最终 URL 必须属于已确认官方域名或其子域名。
- 抓取脚本不硬编码官网必须以`.edu.cn`结尾。
- 已确认官网的 HTTPS 证书异常时，可以改用同一域名的 HTTP 入口；如果跳转到其它域名，必须重新确认域名归属。

## 页面抓取边界

- `scripts/fetch_official_universities.py`一次只抓取一个已确认官网页面。
- 地址不足时可以从同域名的联系、校区和学校概况相关链接中继续选择页面。
- 每所学校最多接受三份页面抓取结果；超过预算必须报错，不得静默截断。
- 保留现有渲染 DOM 的`innerText`与`textContent`读取、隐藏内容读取、节点长度限制和候选数量限制。
- 不恢复`navigation_links`，也不增加高校医学部、研究生院等专有名称规则。
- 页面访问失败时输出结构化警告和空候选，不允许异常堆栈中断整批任务。

## 官网检索与校区地址提取操作总结

准确提取依赖“Agent 找准官网和页面，脚本执行固定解析，公共层处理地址”三层配合，不能只依赖其中一层。

逐页抓取必须保持 Agent 在环：每次工具调用只运行一次`fetch_official_universities.py`并抓取一个页面，完整结果返回 Agent 后，Agent再判断是否停止以及选择哪个同域页面。不得创建批量抓取、自动选页、自动停止或自动生成停止原因的驱动脚本；页面访问失败不能被归类为“已取得明确地址”。

### 第一步：确认学校官网

1. Agent 使用学校全称执行一次 Web Search，优先确认学校主站。
2. 通过页面标题、学校名称、备案信息和搜索结果上下文判断域名归属，不以`.edu.cn`作为唯一条件。
3. 如果搜索结果明确说明学校已经合并或停止独立办学，立即终止该校，不再抓取页面，也不进入地图流程。
4. 只有确认过的官网域名才能传给抓取脚本；跳转到新域名时必须重新确认，不能自动放宽域名范围。

### 第二步：按优先级选择页面

1. 第一页固定从官网首页开始，因为多数学校会在页脚直接列出校区和地址。
2. 首页信息不足时，从脚本返回的`related_links`中优先选择联系页面，其次是明确校区页面，最后是学校简介或概况页面。
3. 每所学校最多抓取三个官网页面。技术性重试不增加业务页面，但不能借重试绕过三页上限。
4. 新闻列表、校园文化、校园风光、地图图片和普通栏目导航不作为补充页面的优先来源。

### 第三步：逐页运行固定提取脚本

每个页面单独调用：

```powershell
python scripts/fetch_official_universities.py <官网页面URL> --official-domain <已确认域名>
```

脚本读取渲染后的 DOM，同时检查可见文本和必要的隐藏文本，输出：

- `address_candidates`：带地址证据的候选；
- `campus_hints`：只有校区名称、暂时没有地址的地点线索；
- `related_links`：下一页可选的同域联系、校区或概况页面；
- `warnings`：访问失败或没有发现明确地址时的结构化警告。

### 第四步：按证据强弱识别地址和校区

可靠性从高到低为：

1. 同一文本块明确写出“校区名称＋地址标签＋地址”，直接形成该校区的地址候选。
2. 页面以“学校地址、通讯地址、联系地址、邮寄地址、办公地址、校址、地址”等通用标签给出地址，但没有校区名称，保留地址并把校区名称留空。
3. “学院地址”或“学校地址”标题下连续列出多行“地址＋邮编＋校区名称”时，逐行拆成不同校区。
4. 一个地址标签后连续出现多组“地址＋邮编”时，按邮编边界拆成多条地址；没有明确校区名称时不得根据区县或道路反推校区名。
5. 页面只明确出现“某某校区、某某校园、校本部”等名称时，生成`campus_hints`，后续使用“学校名称＋校区名称”进行地图兜底。
6. 页脚只有一条无标签地址文字时不强行提取，避免把备案单位、合作机构或其它裸文本误当作学校地址；单校区学校使用学校名称进行地图兜底。

校区名称必须来自地址候选、明确页面正文或名称干净的校区链接。数量描述、新闻标题、宣传语、栏目标题以及“校园生活、校园文化”等文本都不能作为校区名称。

### 第五步：合并页面结果并拆分地点

1. 汇总最多三个页面的`address_candidates`和`campus_hints`，按“校区名称＋去空白地址”去重。
2. 有明确校区和地址时，一个校区生成一条地点记录：`place_name = 学校名称 + 校区名称`。
3. 有多个地址但没有校区名称时，每个地址各生成一条记录，`place_name`均使用学校名称，不编造校区。
4. 只有校区名称时，每个校区生成一条空地址记录并进入地图兜底。
5. 地址和校区名称都没有时，只生成学校名称对应的空地址记录并进入地图兜底。
6. 已确认合并或停止独立办学的学校不生成任何`address_records`。

### 第六步：进入公共地址层前检查

- 页面 URL 和最终跳转 URL 均属于已确认域名；
- 实际抓取页面不超过三页；
- 地址候选没有重复项、残留括号、邮编、电话或邮箱；
- 每条地址都保留`source_text`和页面 URL，能够回看原始证据；
- 校区名称全部来自官网明确文本，没有从地址或学校常识推断；
- 无可靠地址的记录保持空值，由地图兜底处理，不让 LLM 自行补写地址。

## 地址和校区提取

- 地址标签保持通用，不把“广州校区地址”等具体地名写入规则。
- 页面明确给出多个校区和地址时，前置阶段直接拆成多条地点记录。
- 页面只出现明确校区或校园名称但没有地址时，输出有界的`campus_hints`。
- `campus_hints`只来自页面明确文本，不根据区县、道路或其它地址内容推断校区名。
- 新闻标题、栏目标题和宣传语中的“校园”不作为校区线索。
- 页脚只有无标签地址文字时不强行提取；单校区学校允许保留空原始地址并交给地图兜底。
- 同一地址标签后连续出现多组“地址＋邮编”时，按邮编边界拆成多条地址，但不根据地址中的区县名称反推校区名。
- 同一学校存在多个不同地址但页面没有标明校区名称时，拆成多条记录；每条`place_name`均使用学校名称，不编造校区名。
- 如果页面既没有地址也没有明确校区名称，允许以学校名称作为唯一地点名称并把原始地址留空。

联网搜索阶段如果确认学校已经合并或原学校已经停止独立办学：

- 立即停止该校后续页面查找，不调用地图验证或地图兜底；
- 不生成该校的`address_records`，地址和校区相关字段保持为空；
- 不修改教育部名单，也不从离线生成的`base_information.xlsx`中提前删除该校；
- 最终输出阶段统一剔除最终地址为空的记录。

## 公共地址输入组装

高校私有层负责把页面结果转换为公共`address_records`：

- 有明确校区名称：`place_name = 学校名称 + 校区名称`；
- 校区名称已经包含学校全名时直接使用，不重复拼接；
- 没有明确校区名称：`place_name = 学校名称`；
- `original_address`保存页面提取的地址原文，没有地址时为空字符串；
- 高校地址链路的`source_nature`固定为`web_search`，因为教育部高校名单不提供地址，不能把名单性质当作地址来源性质；
- `source_reference`保存支持该地点或地址的页面 URL；页面没有地址时仍保存本次官网检索的可定位依据；
- 高校业务字段通过`attributes`传递，具体保留字段随最终输出方案一起确定；
- 不增加公共流程`id`或`parent_id`，学校标识码属于高校业务字段。

公共地址规范化、地图验证、地图兜底和最终地址路由遵循`.dsh/components/UNIFIED_ADDRESS_STRUCTURE.md`。

## 高校页面结果聚合脚本

`scripts/build_university_address_records.py`负责补齐高校页面批次、校验基础名单完整性并生成公共`address_records`。它只做本地 JSON 处理，不联网、不读取高德密钥，也不执行地址标准化或地图调用。

脚本输入参数为：

- `--input university_retrieval_results.json`
- `--output address_records.json`

Agent只写入语义判断无法自动生成的最小结果。输入顶层只包含`items`：

```json
{
  "items": [
    {
      "school_identifier": "4144010000",
      "processing_status": "completed",
      "pages": [
        {
          "stage": "address_candidates",
          "requested_url": "https://example.edu.cn/",
          "final_url": "https://example.edu.cn/",
          "address_candidates": [],
          "campus_hints": [],
          "related_links": [],
          "warnings": []
        }
      ]
    },
    {
      "school_identifier": "4144010001",
      "processing_status": "skipped",
      "skip_reason": "merged",
      "skip_reference": "https://example.edu.cn/notice"
    }
  ]
}
```

- `completed`只包含`school_identifier`、`processing_status`和`pages`；
- `pages`按实际访问顺序保存一至三个`fetch_official_universities.py`完整输出；
- `skipped`只包含`school_identifier`、`processing_status`、`skip_reason`和`skip_reference`；
- `skip_reason`固定为`merged`或`ceased_independent_operation`，证据必须是HTTP(S)链接；
- 输入不再携带城市、学校名称、完整学校对象、`schema_version`或`stage`；
- 每所基础名单学校必须出现一次，同一学校不得重复。

脚本自动读取输入文件同目录的`base_information.json`，按`school_identifier`匹配学校，补齐标准城市名和完整学校对象，并生成`university_page_results.json`作为审计归档。旧的完整页面批次格式不再作为命令输入。

脚本严格检查名单外学校、重复学校、遗漏学校、非法跳过状态、页面对象结构和三页预算。任一校验失败时不生成可继续进入公共层的结果。

聚合规则固定为：

- 按“校区名称＋去空白地址”合并重复地址；
- 已有明确校区的地址会覆盖同地址的无校区重复项；
- 已经取得地址的校区不再生成空地址校区记录；
- 同一明确校区出现多个不同官网地址时全部保留，并在顶层`warnings`记录冲突；
- 完全没有地址和校区线索时生成一条学校名称空地址记录；
- 输出`attributes`固定使用八个高校英文键并增加`campus_name`，`source_remark`不进入公共属性；
- `source_nature`固定写为`web_search`，`source_reference`使用产生该候选的页面链接。

输出`address_records.json`可以直接作为公共`process_addresses.py`的输入；`university_page_results.json`只用于保留脚本补齐后的完整页面批次和问题追踪。

## 最终 Excel 输出

最终输出以公共层生成的`processed_address_records.json`为唯一输入，一条有效地点记录输出一行。只输出`final_address`非空的记录；已合并院校、无法取得有效地址的记录以及目标城市外地址不进入最终表。

最终工作簿只包含“高校信息”一张表，字段固定为：

| Excel字段 | 内部字段 | 输出规则 |
| --- | --- | --- |
| 序号 | `display_sequence` | 过滤和排序完成后从1开始连续编号，仅用于展示 |
| 学校名称 | `place_name` | 直接使用地图检索同款地点名称，即学校名称与校区名称的组合结果 |
| 主管部门 | `attributes.supervising_authority` | 从教育部名单继承 |
| 办学层次 | `attributes.education_level` | 从教育部名单继承 |
| 院校标签 | `attributes.school_tag` | 输出985、211或空值 |
| 办学性质 | `attributes.school_nature` | 从高校私有预处理结果继承 |
| 最终地址 | `final_address` | 只展示公共层确定的最终地址 |
| 信息来源 | `source_reference` | 展示支持该地点或地址的官网页面链接 |

`place_name`由前置聚合阶段生成：有校区名称时组合学校名称与校区名称；校区名称已经包含学校全称时不重复拼接；校区名称为空时只使用学校名称，不补“校本部”。最终表不再单独输出校区名称。

最终表不展示`source_sequence`、`school_identifier`、`location_city`、独立的`school_name`和`campus_name`，也不展示原始地址、规范地址、地图地址、地图验证状态及处理原因。上述字段继续保留在JSON中供程序处理和问题追踪。

记录先按`attributes.source_sequence`的原始数值顺序排序；同一学校的多条地点记录保持公共输入中的原顺序。排序完成后再生成`display_sequence`。

工作表采用简单固定格式：所有单元格水平和垂直居中，不缩进、不自动换行、不合并单元格；地址列和信息来源列使用固定的适中宽度。表头冻结并启用筛选，信息来源为HTTP或HTTPS链接时写成可点击链接。

输出脚本固定为`scripts/build_excel.py`，只接收公共处理结果和输出文件路径：

```powershell
conda run --no-capture-output -n py3.10 python scripts/build_excel.py --input processed_address_records.json --output 高校建筑查询_广州市_2026-08-26.xlsx
```

## 代码精简审计

- JSON读取、JSON原子写入和工作簿原子保存统一放入`scripts/script_io.py`，业务脚本不再各自维护重复实现。
- 高校检索结果只在组装`university_page_results.json`时校验一次；生成`address_records.json`直接使用已校验批次，不再重复核验相同学校和页面。
- 基础阶段删除无人使用的资产SHA-256、步骤日志、标签计数和办学性质计数，避免名单读取完成后再次遍历完整资产文件；学校明细、学校总数和待核验原因继续保留。
- 官网抓取脚本保留动态页面双快照、地址正则、校区线索和相关链接逻辑；只删除可由`campus_hint`直接推导且没有消费者的`match_type`字段。
- 最终工作簿和校验时打开的工作簿统一关闭，避免连续任务积累文件句柄。

## 真实页面测试规则

- 真实官网抓取测试必须先从内置教育部名单中筛选目标城市高校，再随机抽取学校。
- 每次测试记录本次随机抽中的学校名称，不长期固定使用少数熟悉高校作为真实样本。
- 固定构造数据只用于单元测试具体边界，不能替代随机高校官网测试。
- 随机测试发现的错误应修正规则本身，不把本次学校名称或地名写入通用正则。
- 修复后先回归当前样本，再排除全部已测学校并随机抽取下一批；只有新一批样本全部符合既定提取或兜底边界时才结束本轮验证。
